## M-01 재진입 가드
- `start()`: `set({status:'requesting'})` 직후 `if (disposed || !live()) return;` → 알림 안에서 dispose·cancel·reset되면 `r.start()`를 부르지 않음(마이크 켜지지 않음).
- `onstart`/`onspeechend`: `armTimer`를 `set()`보다 **먼저** 호출해 알림 안의 정리가 마지막 작업이 되게 통일.
- 테스트: requesting 알림에서 dispose/cancel/reset → `started === 0`, 타이머 0, 상태 열(`['requesting']` / `[…,'aborted']` / `[…,'idle']`). listening·processing 알림에서 dispose/cancel → 타이머 0.

## M-02 requesting 기한
- `export const STT_REQUEST_TIMEOUT_MS = 15000`, `SttOptions.requestTimeoutMs?` 주입 가능. 가드 뒤·`r.start()` 전에 설치, 만료 시 `timeout`(retry·showStaff). `onstart`에서 listening 8초로 교체.
- 헤더 주석: "requesting 15초 / listening 8초 / processing 8초", 실측은 T4.3.
- 테스트: 기존 "requesting은 타임아웃하지 않는다" 대체 → 14 999ms requesting, 15 000ms timeout. 기한 전 onstart → 8초 재설정. requesting 중 cancel/dispose 후 타이머 0. 주입값 동작.

## M-03 음성 목록 동기 재확인
- `refreshVoice()`(동기): `getVoices()`에서 다시 고름 → 찾으면 `ready`, 없으면 `voice=null`·`no-korean-voice`(init 완료 후에만). **목록이 비어 있으면 판단을 바꾸지 않음**(안전한 기본값: 로드 전 빈 목록으로 강등하지 않음).
- `speak()`: 사용자 탭 안에서 await 없이 `refreshVoice()` 후 발화.
- `init()`: 진행 중 탐색만 합침(`searching`). 완료 후 호출 시 `refreshVoice()`로 즉시 확인, `ready`가 아니면 다시 최대 2초 탐색. 상시 `voiceschanged` 구독은 도입하지 않음(판정 4).
- 테스트: 진행 중 탐색 합치기(리스너 1개), 2초 경과 no-korean-voice → 한국어 추가 → init `ready`, 같은 상황 speak가 새 음성 지정·`ready`, 고른 음성 제거 시 다른 음성/없음으로 교체, 빈 목록 시 유지.

## L-01 onEnd 계약 (발화 요청당 정확히 1회)
- 헤더 계약: 끝·오류이면 그때, 새 `speak()` 선점·`cancel()` 시 즉시(동기), 그 발화의 늦은 end/error는 무시. `'started'`는 큐 제출 의미(재생 성공 보장 아님)도 명시.
- 구현: `current: Entry{u,onEnd,done}`, `finish()`는 `done` 가드 + 핸들러 해제. 선점된 이전 발화의 `finish`는 **새 발화를 큐에 넣고 current로 지정한 뒤** 호출 → onEnd 안에서 다시 speak해도 안전.
- 목 확장: `MockSynth.cancel`이 큐의 발화에 **마이크로태스크로 늦은 `onerror`(interrupted)** 를 보냄, `endFront()`로 정상 종료.
- 테스트: 선점 시 onEndA 1회·onEndB 0회(늦은 interrupted 후에도), cancel 시 즉시 1회·추가 없음, 정상/오류 종료 1회, 동기 error를 보내는 cancel 변형에서도 1회, onEnd 안 재-speak.

## nit
- A-1: `dispose()`에서 알림 없이 `state = {status:'idle'}`(미지원이면 그대로) → 내부 원문 제거. 테스트 추가.
- A-2: processing→onend 무결과 → `no-speech`, error→end 순서에서 error 유지(캡처한 onend 직접 호출), retry 전 캡처한 이전 핸들러 5종을 retry 후 직접 호출해도 새 시도 불변(세대 가드) 테스트 추가.
