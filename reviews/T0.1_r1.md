### 허용 목록 해석

루트 규칙은 `*`가 아니라 **`/*`**다. 루트의 디렉터리를 `!/app/`, `!/.github/` 등으로 다시 포함하면, 그 아래 일반 파일까지 `/*`가 재귀적으로 막지는 않는다. 따라서 이 구성에 `!/app/**`·`!/.github/**`를 추가할 필요는 없다. 마지막에 둔 `**/node_modules/` 등과 `**/.env*`는 허용 디렉터리 내부에도 적용된다. 위 가상 경로 검사는 파일을 생성하지 않고 수행했다.

검토 도중 다른 작업에서 생긴 `app/.gitignore`도 읽어 확인했다. 현재 내용은 산출물 추가 제외이며, 루트의 비밀값 제외를 재포함하는 규칙은 없다. 앱 소스 자체의 품질 검토는 이번 범위가 아니다.

## 2. 미해결 항목

### L-01 — 제출한 파일 목록이 실제 첫 커밋 인덱스의 증거로 확정되지 않았다

- **위치:** `reviews/T0.1_files.txt` 전체, `task.md` 57·86·88행.
- **증거:** 검토 시 `git ls-files` 결과는 0건, `git status`의 허용 파일은 모두 `??`, `git log -1`은 아직 커밋이 없다고 응답했다. 반면 제출 목록은 20개 경로다. 따라서 현재 파일을 실제 stage된 공개 대상 전체 목록으로 검증할 수 없다.
- **추가 관찰:** `git ls-files --others --exclude-standard`는 검토 중 42건까지 늘었으며, 제출 목록에 없는 `app/package.json`, `app/package-lock.json` 등 앱 파일이 포함됐다. 병행 구현이 진행되는 상황으로 보이며, 이 파일들이 허용 경로에 있다는 사실 자체는 결함이 아니다. T0.1만 선택해 stage할 경우 앱 파일을 첫 목록에 넣지 않아도 된다.
- **영향·심각도:** 제외 규칙은 정상이고 실제 개인정보 유출도 확인되지 않았다. 다만 이 목록만으로 ‘첫 push 대상의 개인 자료 0건 검사가 끝났다’고 선언하면 검사한 집합과 실제 커밋 집합이 달라질 수 있다. 공개 전 증거의 확정 문제로 **Low**다.
- **최소 보완:** coordinator가 실제 첫 커밋 대상 경로를 선택해 stage한 뒤, 그 인덱스의 `git ls-files` 결과로 목록을 확정하고 재대조한다. 이 보고서 등 새 reviews 파일도 포함 여부를 정해 동일한 목록에 반영한다. 현재 파일이 임시 인덱스에서 만든 사전 목록이라면 그 생성 방식·대상을 기록하고, 공개 전에는 실제 인덱스와 일치함을 확인하면 된다.
- **닫힘 기준:** 첫 커밋 직전 실제 `git ls-files`와 목록의 경로 집합이 같고, 허용 경로 밖·빌드 산출물·개인 자료가 0건임을 확인한다. 검토자가 파일을 stage하거나 목록을 임의 변경하지는 않았다.

## 3. README·reviews 내용 검사

- README의 문서 링크 대상은 존재한다. 실행 명령은 T0.2에서 준비할 앱 계약과 일치하지만 이번 검토에서 앱 실행 성공이나 배포 URL의 서비스 상태까지 시험한 것은 아니다.
- reviews의 기존 파일은 모두 Markdown 또는 파일 목록 텍스트다. 토큰 형식(GitHub·API 키 등), private key 헤더, Bearer 값, 비밀번호/secret 대입, 이메일·휴대전화·주민등록번호 후보, 사용자 홈 절대 경로 등을 검색하고 후보 문맥을 확인했다.
- 휴대전화 형태 후보는 승인된 GitHub 계정 식별자가 들어간 배포 URL·API 경로였다. 이를 별도의 비공개 연락처 유출로 세지 않았다. 로컬 경로 후보 상당수도 `https://`를 잘못 잡은 결과였으며, 사용자 홈 경로를 겨냥한 후속 검색에서는 발견하지 못했다.
- `개인정보`, `연락처`, `음성 저장` 등의 검색 결과는 앱 요구사항·고지·후속 연락처 지정 계획에 관한 설명이었다. 실제 비밀값이나 신청자의 개인정보 원문은 확인하지 못했다.
- 일부 과거 보고서는 비공개 자료의 **상대 파일명**을 참고 자료로 적지만 자료 내용이나 개인정보를 복사한 것은 확인되지 않았다. 공개 승인된 reviews의 검토 이력이라는 맥락에서 별도 결함으로 세지 않았다.
- 이는 현재 파일의 정적 검토 결과다. 앞으로 reviews에 추가되는 파일까지 검사했다는 의미는 아니므로, 최종 공개 대상은 L-01의 실제 목록 확정 시 함께 확인한다.
