## 수정 요청

### T2.2-M-01 — 일부 타일 수신 후에는 실패·정체가 지속되어도 약도로 전환하지 않음

- 위치: `app/src/ui/map/LeafletMap.tsx:63–82`, `LeafletMap.test.tsx`의 타임아웃·오류 임계값 테스트.
- 문제: 성공 타일 수 `loaded`가 한 번이라도 증가하면 8초 타이머는 아무 일도 하지 않는다. 이후 실패가 1~2개에 그치거나 나머지 요청이 계속 pending이면 일부가 빈 지도에 머무른다. 초기 로드 뒤 지도 이동·확대로 새 타일 요청이 멈추는 경우에도 기한을 다시 설정하지 않는다. `navigator.onLine`이 true인 채 OSM만 느리거나 차단된 경우에 해당한다.
- 근거: `tileload` 1회 → `tileerror` 1회 또는 2회 → 8초 경과라는 이벤트 순서에서 `loaded !== 0`, `errors < 3`이므로 `onFail`이 호출되지 않는 것이 코드상 확정된다. 기존 테스트는 성공 1회 뒤 16초를 기다려도 실패하지 않는 것을 기대하므로 이 결함을 잡지 못한다. PRD 7·8장과 T2.2는 타일 실패 시 약도 전환을 요구한다. 첫 성공 타일 하나는 화면 전체 지도를 사용할 수 있다는 증거가 아니다.
- 권장 수정안: 현재 뷰의 타일 로딩 배치 단위로 완료·실패·미완료를 추적하고, 실패 또는 미완료가 기한을 넘으면 약도로 전환한다. 단발성 오류를 허용하려면 제한된 재시도/유예 뒤에도 실패가 남으면 전환하도록 한다. 일부 성공+1개 실패, 일부 성공+pending, 초기 성공 후 새 배치 정체를 검증하고, 정상 배치 완료 때 타이머를 해제한다. 타일을 대량 재요청하는 방식은 피한다.

### T2.2-M-02 — 지도 컨트롤과 작은 화면 약도 핀의 실제 터치 영역이 44px 미만

- 위치: `app/src/ui/map/LeafletMap.tsx:54`, `app/src/ui/map/map.css:6–21`, `app/src/ui/map/SketchMap.tsx:45,100`, `SketchMap.test.tsx`의 터치 영역 검사.
- 문제: Leaflet 기본 확대·축소 컨트롤을 켜면서 크기를 덮어쓰지 않았다. 설치된 Leaflet CSS는 링크를 일반 환경 26×26px, 터치 환경 30×30px로 만든다. 약도는 반지름 22인 SVG 원을 44 CSS px로 간주하지만 viewBox와 함께 축소된다. 360px 뷰포트에서는 좌우 margin 32px와 border 2px를 제외한 내부 폭이 326px이므로 지름은 약 `44 × 326 / 360 = 39.84px`이다. 390px에서도 내부 폭 356px이므로 약 43.51px이다.
- 근거: PRD 7장의 버튼 터치 영역 44px 이상 요구. `reviews/T2.0_usage.md`도 화면 소유자가 전용 CSS를 책임지도록 명시한다. 설치된 `leaflet/dist/leaflet.css:288–328`과 대상 CSS의 계산 결과이며, 새 브라우저 측정은 하지 않았다. 기존 약도 테스트는 SVG의 `r` 속성만 검사해 CSS 크기 변환을 놓친다.
- 권장 수정안: 지도 범위에 한정한 CSS로 확대·축소 컨트롤을 최소 44×44px로 확장한다. 약도 핀은 CSS 픽셀 기준의 HTML 오버레이를 사용하거나 최소 지원 폭에서도 44px 이상이 되도록 투명 히트 영역을 확장한다. Phase 2 브라우저 검증에서 360·390·430px 실제 렌더 크기를 확인한다.

### T2.2-L-01 — 확대·축소 버튼의 접근성 이름이 일본어·중국어에서 영어로 남음

- 근거: 설치된 `leaflet/src/control/Control.Zoom.js:25–35`의 기본값을 그대로 사용한다. T1.2의 ja·zh 영어 fallback 없음 및 Phase 2 언어 전환 기준에 비해 누락된 UI 문구다. 라이브러리 내부 문자열이므로 앱 소스의 하드코딩 검사 통과만으로 검출되지 않는다.
