## T2.1-M-01 — 언어 라디오 그룹 키보드 동작 → 수정 완료

판정 권장안 1(네이티브 radio)을 적용했습니다.

| 파일 | 변경 |
|---|---|
| `app/src/screens/Lang/index.tsx` | `<button role="radio" aria-checked>`를 `<label className="lang-opt">` + `<input type="radio" name="lang-choose" value checked onChange={setLang} className="sr-only">`로 바꿈. 컨테이너 `role="radiogroup" aria-labelledby="lang-choose"`는 유지. `lang` 속성·`data-testid="lang-<code>"`(label)·`lang-opt--on` 선택 스타일 유지 |
| `app/src/screens/Settings/index.tsx` | 같은 방식, `name="set-lang"`. `Card role="radiogroup" aria-labelledby="set-lang"` 유지, `data-testid="set-lang-<code>"`(label) 유지 |
| `app/src/screens/Lang/lang.css`, `app/src/screens/Settings/settings.css` | `.lang-opt`/`.set-opt`에 `position:relative; cursor:pointer`. 포커스 표시를 `:focus-visible`에서 `:has(input:focus-visible)`로 옮김. 44px 최소 높이(`--touch`)는 label에 그대로 있음 |

- 숨김 input에는 기존 공용 유틸 `.sr-only`(`styles/global.css`)를 사용했습니다. 공용 styles는 수정하지 않았습니다.
- 방향키로 옮기면 네이티브 radio가 change를 보내므로 선택 즉시 언어가 전환됩니다(F-01).
- 첫 실행(lang null)에서 EN이 checked로 보이는 동작과, "시작하기"를 누를 때 EN을 저장하는 동작은 그대로입니다.

## 테스트 (화면당 회귀 테스트 추가)

- 기존 `aria-checked` 검사를 `toBeChecked()`/`not.toBeChecked()`로 바꿨습니다. 기존 클릭 테스트는 그대로 둡니다.
- `Lang.test.tsx` +4개: 같은 name의 radio 3개·그룹 이름·하나만 checked / 다음 radio change → store·문구 즉시 전환·이전 항목 해제 / 라벨(카드 전체) 클릭으로 선택 / 언어 항목이 button이 아니며 tabindex 조작이 없고 화면의 button은 "시작하기" 하나뿐.
- `Settings.test.tsx` +3개: 같은 name의 radio 3개·그룹 이름·하나만 checked / change → 즉시 전환·이전 항목 해제 / 라벨 클릭으로 선택.
- jsdom은 네이티브 radio의 방향키 이동을 재현하지 않습니다. 그래서 테스트 주석에 "방향키 동작은 브라우저 기본 동작에 맡긴다"고 적었습니다(판정 지침 3).
