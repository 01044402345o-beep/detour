## M-01 — 자정 이후 영업 구간에 전날 휴무가 반영되지 않음

- **위치:** `app/src/screens/Place/hours.ts:57–59`, `hours.test.ts`.
- **문제:** 자정 넘김 영업에서도 현재 달력 요일만 휴무인지 검사한다. `18:00–02:00`, 월요일 휴무인 경우 화요일 01:00을 영업 중으로 표시하지만, 해당 구간은 휴무였던 월요일에 시작했어야 하는 영업이다. 반대로 일요일 영업의 연장인 월요일 01:00은 즉시 종료로 처리한다.
- **근거:** F-04 및 T2.3의 등록 시간표 기준 상태 계산. 실제 hours.ts를 TypeScript로 메모리 내 변환하여 호출한 결과 `2026-11-23T01:00:00+09:00 → closed`, `2026-11-24T01:00:00+09:00 → open`을 확인했다. 기존 테스트는 자정 넘김과 휴무일을 별도로만 검사한다. 현재 정적 데이터에는 이 조합이 없어 기존 네 장소에서 즉시 나타나는 문제는 아니다.
- **권장 수정안:** 자정 넘김의 `minutes < end` 구간에서는 전날을 영업 시작 요일로 판단하고, `minutes >= start`에서는 당일 휴무 여부를 사용한다. 휴무일 다음 날 새벽 및 휴무일 당일 새벽, 종료 경계 테스트를 추가한다. 휴무일을 달력 날짜 전체 폐쇄로 해석할 의도라면 그 정책을 명시하고 전날 휴무 다음 날의 잘못된 개점도 별도로 막는다.

## M-02 — 메뉴·문장 탭에서는 영업 상태의 참고값 안내가 사라짐

- **위치:** `app/src/screens/Place/index.tsx:125–129`, `app/src/screens/Place/InfoTabs.tsx:50`.
- **문제:** 헤더의 `Open now`/`Closed now`는 모든 탭에서 보이지만, 한국 시간의 등록 시간표 기준 참고값이라는 설명은 HowTab 안에만 있다. 주문 가능한 장소의 기본 메뉴 탭과 문장 탭을 보는 사용자는 계산된 상태를 실시간 영업 확인 결과로 오해할 수 있다. 확인 전 배지는 정보 전체의 검증 상태이며, 영업 상태 계산의 의미를 대신 설명하지 못한다.
- **근거:** PRD F-04·task T2.3의 “영업 상태(Asia/Seoul 기준 참고값)”. 제공된 캡처의 S03 메뉴 및 S04 문장 화면에서도 상태만 표시되고 참고 안내는 없다. `place.statusNote`는 이미 3개 언어로 존재한다.
- **권장 수정안:** 상태를 표시하는 헤더 근처에 기존 `place.statusNote`를 함께 표시하거나 모든 탭에서 보이는 공통 위치로 옮긴다. 메뉴·이용 방법·문장 탭 각각에서 안내가 노출되는 컴포넌트 테스트를 추가한다.

## L-01 — 같은 장소로의 새 navigation에서는 state.tab을 재적용하지 않음

- **위치:** `app/src/screens/Place/index.tsx:43`, `index.tsx:69`.
- **문제:** `location.state.tab`을 useState 초기화에만 사용하고 PlaceView key는 장소 ID뿐이다. 같은 `/place/ssd`가 유지된 상태에서 새 history entry로 `{ tab: 'menu' }` 등을 전달하면 location은 바뀌어도 기존 선택 탭이 남는다. 현재 S09에서 돌아오는 경로는 화면이 재마운트되므로 정상이며, 같은 장소 내 navigation에 한정된 결함이다.
- **근거:** 코드가 명시한 state.tab 계약과 T2.3 검토 항목. 기존 테스트는 초기 진입 state만 확인하고 동일 ID 재이동을 다루지 않는다.
- **권장 수정안:** location.key가 바뀔 때 유효한 state.tab을 재적용하거나 navigation entry 기준으로 탭 상태를 초기화한다. 사용자가 탭을 직접 누를 때 다시 초기화되지 않도록 하고, 동일 장소로 두 번 이동하는 회귀 테스트를 추가한다.

## 확인된 적합 사항 및 차이 판정

- **시트 중첩:** 단일 `sheet: 'report' | 'switch' | null` 상태로 ReportSheet와 SwitchPlaceSheet를 상호 배타적으로 연다. T2.0 겹침 미지원 계약 준수. ReportSheet는 직접 import하며 제보 이벤트를 중복 기록하지 않는다.
- **store 액션:** 다른 장소에 담기는 switchPlace 결과를 확인한 뒤 보류하며, 확인 시 confirmSwitchPlace 다음 increment를 호출한다. 취소·Esc는 cancelSwitchPlace로 기존 주문을 유지한다. increment/decrement는 store의 setQty와 동일한 writeQty를 거치므로 수량 직접 수정이나 제한 우회가 아니다. 1에서 감소 시 삭제, 9에서 증가 시 유지·안내를 테스트한다.
- **포장·문장:** useOrderView가 effectiveTakeout을 사용하고, takeout:false에서 전환을 숨기고 문장에서도 포장을 제거한다. 문장·발음·번역은 domain/orderSentence 결과를 그대로 표시한다. F-06 문장 틀, 빈 주문 시 행동 버튼 비활성, 수량 변경 후 문장 갱신을 확인했다. staff_shown은 S08에서 기록하므로 주문 화면에서 기록하지 않는 것이 맞다.
- **가격·정보:** priceKrw 부재는 가격 확인 필요, 하나라도 부재하면 합계를 총액 확인 필요로 표시한다. verified:false는 날짜 대신 확인 전 배지로 표시한다. 알레르기 미확인 및 비제휴 안내, 네이버 기본·Google Maps 보조 링크, 장소 저장 액션 및 저장소 반영을 확인했다. UI 문구는 사전·콘텐츠 데이터를 사용하며 SVG 장식 값과 숫자 포맷을 사용자 문구 하드코딩으로 보지 않는다.
- **접근성:** 수량 버튼과 최초 추가 버튼은 CSS상 44×44px이고 메뉴 이름을 포함하는 번역 aria-label을 갖는다. 장소 탭·길찾기·주문 방식 버튼에도 44px 최소 높이가 있다. 실제 모든 폭에서의 터치 영역 및 글씨 크게 모드 검증은 phase E2E에 남는다.
- **00:00–24:00 원문:** 은행동의 데이터 값이 숫자 시간 구간으로 그대로 표시된다. 목업의 `Always open`보다 즉각적인 의미 전달은 약하지만 하루 전체 구간을 정확하게 나타내며, 언어별 영어 하드코딩도 발생하지 않는다. 별도 결함으로 세지 않는다. 향후 “24시간” 번역 표시는 선택적 사용성 개선이며, 이를 LED 공연의 상시 운영 의미로 확장해서는 안 된다.
- **목업 차이:** 확인 전 배지, 미확인 가격, 매장 전용 배지, 참고 안내 및 보조 지도 링크는 PRD·최신 데이터에 따른 타당한 차이다. 44px 버튼 확장, 대비를 높인 주황색, 느리게 듣기 설명 확장은 접근성 목적에 부합한다. 제공된 캡처에서 핵심 카드·일러스트·간격 구조는 목업을 유지한다. 장소 전환 확인 시트는 목업에 없더라도 F-05에 필요한 추가 구현이다.
