## M-01 — 타당, Medium 유지

**사실 확인**
- `Practice/index.tsx:146-157`의 `onMic`·`retry`는 `sttRef.current?.start()`만 부르고, TTS는 취소하지 않습니다.
- 듣기 버튼 세 종류(`:200-209` 보통·느리게, `:218-229` 단어 칩)는 `active`(requesting·listening·processing) 상태와 상관없이 항상 누를 수 있습니다. 비활성 조건은 `ListenButton.tsx:124`의 `state === 'unsupported'`뿐입니다.
- ListenButton의 취소 계약(`ListenButton.tsx:39-46` ①~④)은 언마운트와 다른 TTS 요청의 선점만 다룹니다. 같은 화면에서 STT가 시작되는 것은 알 수 없습니다. `speech/stt`·`tts` 어댑터도 서로를 참조하지 않으므로, 두 음성 경로의 상호 배제를 맡을 곳은 두 경로를 함께 쓰는 S06 화면입니다.
- 결과적으로 "듣기 → 바로 마이크"라는 정상 순서에서 스피커로 나오는 정답 음성이 인식 입력에 섞일 수 있습니다. 이렇게 섞인 음성이 F-09 점수와 `practice_done` 기록을 부풀릴 수 있습니다. 실기기 반향은 실측하지 않았지만 코드 경로로 재현이 분명합니다.

**심각도**: 핵심 흐름(F-08→F-09)의 결과가 오염될 수 있지만 크래시나 데이터 유출은 아닙니다. 수정은 T2.4 소유 파일 안에서 끝낼 수 있습니다. Medium을 유지합니다.

**수정 지침 (모두 `screens/Practice*` 안에서 처리, 공용 ui 변경 불필요)**
1. `PracticeView`에서 `const ttsInst = tts ?? getTts();`로 ListenButton과 같은 인스턴스를 구합니다(`getTts`는 `speech/tts.ts:197`의 공용 싱글턴).
2. `onMic`의 시작 경로와 `retry`에서 `sttRef.current?.start()` 전에 `ttsInst.cancel()`을 부릅니다. `tts.ts:14` 계약상 cancel은 onEnd를 동기로 호출합니다. ListenButton ③(자기 요청 번호 확인)에 따라 재생 중이던 버튼의 `aria-pressed`/재생 표시가 꺼지므로 따로 정리할 것은 없습니다.
3. 인식이 진행 중인 동안에는 듣기를 막습니다. `.pr-ctrl`과 `.pr-words`를 각각 `<fieldset disabled={active}>`(테두리·여백 리셋 CSS 포함)로 감싸거나 공통 래퍼 하나로 감쌉니다. 이렇게 하면 ListenButton API를 바꾸지 않아도 안의 버튼이 모두 비활성화됩니다. 의미 없는 fieldset이 되지 않도록 `legend`는 생략하거나 기존 `pr-label`을 legend로 옮겨도 됩니다.
4. 컴포넌트 테스트를 추가합니다(기존 `testFakes.ts`의 TTS·STT 가짜 객체 사용).
   - 듣기 → 마이크: `tts.cancel` 1회 호출, 재생 표시(`aria-pressed`) false.
   - listening 상태에서 '듣기'·'천천히 듣기'·단어 칩이 disabled이고 클릭해도 `speak`가 호출되지 않음.
   - 실패 → 듣기(활성) → 재시도: 재시도할 때 `tts.cancel`이 호출됨.

## L-01 — 타당, Low 유지

**사실 확인**
- `resultState.ts:26`은 `scoreSpeech`의 `words`(공백 토큰, `scoring.ts:45-50`의 `tokenize`)를 그대로 결과 칩으로 씁니다. 그래서 S06 칩 `두 개`(`orderSentence.ts:102`, 수량 1칩)가 S07에서는 `두`/`개` 두 칩이 됩니다. `개`만 틀리면 팁도 `개`만 가리킵니다.
- 목업 S07은 S06과 같은 학습 단위(`ph.w`)를 씁니다. 총점 계산은 정상이고 F-09는 공백 토큰화를 금지하지 않으므로, 학습 단위 일관성 문제로 보고 Low가 맞습니다.

**수정 지침 (Result·Practice 안에서만, `domain/scoring` 수정 금지)**
1. `toResultState(nav, r, units)`에 S06 학습 단위 `item.words.map(w => w.ko)`를 넘깁니다(`Practice/index.tsx:111` 호출부).
2. 단위마다 `tokenize(unit).length`(scoring에서 이미 export된 함수)로 차지하는 토큰 수를 구해 `r.words`를 **순서대로 구간 분할**합니다. 텍스트 검색으로 병합하지 마십시오. `주세요`·`개`가 한 문장에 여러 번 나오기 때문입니다.
   - 단위의 `matched` = 구간 토큰이 모두 matched.
   - `weakestIndex` = 원래 `r.weakestIndex`가 속한 단위의 인덱스.
3. 단위 토큰 수의 합이 `r.words.length`와 다르면(데이터 불일치) 지금처럼 토큰 단위로 표시합니다. 개발 모드에서는 경고합니다. 주문 문장은 `orderSentence.test.ts:135`가 `words.join(' ') === strip(ko)`를 보장하지만, 일반 문장 데이터에는 같은 검사가 없으므로 이 대비책이 필요합니다.
4. `parseResultState`의 `clean[weakestIndex].matched` 검증은 단위 기준으로도 그대로 성립합니다(약한 단위는 반드시 불일치).
5. 테스트를 추가합니다.
   - `두 개` 완전 일치 → 칩 1개 ok.
   - `두 개 → 두`(개 누락) → `두 개` 칩 1개 ng + 팁 대상 `두 개`.
   - `두 개 → 세 개` → 칩 ng.
   - 수량이 두 번 나오는 주문(튀김소보로 2·판타롱부추빵 1) → 각 단위가 자기 구간만 반영.
   - 단위 수 불일치 데이터 → 토큰 단위 대비책.

## L-02 — 타당, Low 유지 (팁: T2.4 수정 / 칩: coordinator 조율)

**사실 확인**
- 팁: `Result/index.tsx:116`의 `<span>{t('result.tip', { word: weak.ko })}</span>`는 한국어 단어를 사용자 언어 문자열에 그대로 끼워 넣으므로, 한국어 부분에 `lang="ko"`가 없습니다.
- 칩: `Practice/index.tsx:223`이 `label={\`${w.ko} · ${meaning}\`}`을 넘깁니다. `ListenButton.tsx:122`는 bare·children 조합에서 항상 `aria-label=name`을 붙이므로, 자식 `<span lang="ko">`의 언어 정보가 접근 가능한 이름에서 사라집니다.
- `label`을 빼더라도 ListenButton은 `t('audio.listen')`('Listen')으로 대신 채웁니다(`:105`). 그래서 T2.4 안에서 칩 쪽은 고칠 수 없습니다. 공용 `ui/` 소유자(T2.0) 계약 변경이 필요합니다(task.md 0.2절).
- 실제 낭독 오독은 기기마다 다르므로 Low가 맞습니다.

**수정 지침**
1. (T2.4, 지금 반영) 팁 템플릿의 `{word}` 자리를 노드로 렌더링합니다. 예: `const [pre, post] = t('result.tip', { word: '\u0000' }).split('\u0000');` → `<span>{pre}<span lang="ko">{weak.ko}</span>{post}</span>`. 번역 사전은 바꾸지 않습니다. 분할 결과가 2조각이 아니면 지금 방식으로 표시합니다. 테스트에서는 팁 안의 `[lang="ko"]` 텍스트가 `weak.ko`인지 3개 언어 각각 확인합니다.
2. (공용 API, coordinator 조율) ListenButton에 "보이는 내용을 이름으로 쓰기" 옵션을 추가합니다. 예: `label={null}`이면 `aria-label`을 생략합니다. 이 변경을 coordinator에게 요청하고, 반영되면 S06 칩에서 `label`을 제거해 이름이 `<span lang="ko">두 개</span><small>two</small>`에서 계산되게 합니다. 이 변경이 Phase 2 안에 들어가지 않으면 T2.4 미해결에서 이관 항목으로 분리하고 T4.3 TalkBack 점검 목록에 "단어 칩 한국어 발음 전환"을 넣는 것도 허용합니다(coordinator 결정).
3. T4.3 실기기 점검 항목에 S06 단어 칩과 S07 팁의 낭독을 추가합니다.
