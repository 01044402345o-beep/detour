## M-01 — 새 모듈의 행선지 선택이 데모 초기화 후에도 남음

- 위치: `app/src/screens/Course/walkPick.ts:7–19`, `app/src/screens/Course/index.tsx:143–151`. 관련 기존 초기화 경로: `app/src/screens/Settings/index.tsx:191–195`, `app/src/store/useAppStore.ts:321`.
- 재현 절차: 원도심에서 3번을 선택 → 설정 > 시연 도구 > 데모 데이터 초기화 확인 → 인트로/홈을 거쳐 같은 코스 진입. 기록은 비워져 Next가 1번이지만, 선택·네이버·Google 목적지와 버튼 문구는 여전히 3번이다. 시장 코스도 동일하다.
- 근거: `picks`는 화면 밖 Map이고 `resetWalkPicks` 호출은 테스트의 beforeEach에만 있다. 실제 초기화는 store의 데이터만 비운 뒤 SPA 내부 `navigate`를 하므로 모듈은 다시 로드되지 않는다. 코스가 다시 마운트되면 Map의 이전 선택을 복원한다. 이는 코드 경로로 확인한 결과이며 실제 브라우저 초기화 재현은 수행하지 않았다.
- 영향: 사용자에게 “Delete all demo data on this device and start over?”라고 안내하는 기존 초기화가 새 선택 상태를 지우지 못해, 다음 시연이 첫 정류장부터 시작하지 않는다. R1의 상세 왕복 보존을 위해 도입한 상태 수명이 명시적 초기화까지 넘어간 회귀다.
- 수정: 상세 왕복에서는 선택을 유지하되, 명시적인 데모 초기화에서는 두 코스의 선택을 모두 비우도록 초기화 수명을 연결한다. 공용 store/Settings 변경이 필요하면 coordinator와 범위를 조율한다. 단순히 events가 비었다는 이유로 매번 지우면 기록이 없는 상태에서의 수동 선택·왕복 보존이 깨질 수 있다.
- 검증: 두 코스에 수동 선택을 남긴 뒤 실제 초기화 동작을 실행하고, 각 코스의 선택·Next·두 지도 주소·시작 문구가 1번으로 돌아오는 테스트를 추가한다. 기존 상세 왕복 보존 테스트도 유지한다. 현재 테스트는 매번 `resetWalkPicks()`를 직접 호출하므로 실제 초기화 누락을 발견하지 못한다.

## 기준·회귀·테스트 검토

- `task.md` Phase 6 머리 규칙과 T6.13, DESIGN.md v1.1, prd.md의 F-03·S02 및 관련 초기화 경로, 작업 보고·R1·판정, 소유 코드 diff를 확인했다. 현재 PRD v0.12 변경은 요청된 행선지 선택 추가를 반영한다.
- 네이티브 radio의 같은 name, fieldset/legend, 전체 이름을 포함한 aria-label, 숨겨도 초점 가능한 input을 유지한다. 44px 최소 칸과 `:has(input:focus-visible)` 3px 외곽선이 있고 전역 reduced-motion 규칙이 transition을 끈다. 글자는 ink/mute/blue 대비 토큰을 사용하고 앰버 배지에는 ink 글자가 있어 색만으로 Next를 전달하지 않는다.
- 수동 선택과 Next의 계산은 분리되어 있다. 고르기 전에는 방문 기록을 따라가고, 명시적 선택 이후에는 기록이 바뀌어도 목적지를 보존한다. 선택 자체는 place_view를 추가하지 않으며 기존 장소 이동·이벤트 기록 경로를 바꾸지 않았다.
- `screen-course`, `stop-<id>`, `start-walking`, `google-maps` 계약과 외부 URL 생성 함수를 유지한다. `app/e2e/support.ts:108`의 정류장 클릭 경로도 유효하다.
- 기존 테스트 삭제 없음. 변경된 안내의 기대값 3곳만 dirTo로 바꾸고 선택·복귀·이름 검사를 추가했다. 복귀 테스트는 실제 라우터 왕복 대신 언마운트/이벤트 주입/재마운트로 핵심 상태 수명을 검사한다.
- 번역 패치의 세 키는 EN/JA/ZH 적용 결과와 일치한다. JA 전각 물음표·「」, ZH 전각 물음표·“”와 문구 의미는 적절하다. 잘리는 선택 칸 이름은 디자인상 말줄임이며 전체 이름은 안내와 접근성 이름에 제공한다.
- 새 `walkPick.ts`는 task 소유 목록에 아직 열거되지 않았지만 R1 판정에 명시된 해결용 모듈이고 이번 검토 지시가 포함하도록 지정했다. 공용 store/router 수정은 없다. 문서·번역 변경도 T6.13 관련이며, 공유 번역 파일의 실제 작성 주체는 diff만으로 확정할 수 없다.
- 사진·빈 alt·사진 출처·음식 예시 표시·확인 전 요약/혼합 정책은 변경하지 않았다. 새 사진이나 글자 막은 추가되지 않았다.

## 화면 확인 및 한계

`mockup/redesign/c2-course.png`, 제공된 `course-360-ja.png`, `course-market-360-zh.png`, `keyboard-focus-360-en.png`를 직접 열었다. 시안의 지도·밝은 파랑 구성에 요청한 2×2 선택이 추가되었고, 선택 3번과 Next 1번은 구분된다. 확인한 캡처에서 가로 넘침이나 선택 칸끼리의 겹침은 보이지 않는다.

전체 화면 캡처는 일본어가 아직 `どこへ歩きますか?`로 표시되는 등 R1 수정 전 자료이므로, 최종 일본어 문구와 배지 확대 후 배치의 시각 증거로 사용할 수 없다. 최신 초점 캡처는 일부 하단 영역만 보여준다. 최종 문구·배지 크기는 코드로 확인했다.

dock은 정상 흐름을 유지하는 sticky 요소이고 notes가 앞에 있으며 하단 간격이 있다. 목록/노트를 영구히 가리는 구조적 오류는 확인하지 못했지만, 고정 영역이 커져 초기 노출을 줄이는 점은 그대로다. 제공 캡처로는 스크롤 끝·낮은 화면·확대 글꼴에서 전체 노트 도달성을 입증할 수 없다.

다른 task를 포함한 tsc/lint 오류도 이번 실행에는 없었다. E2E는 허용 실행 목록에 없어 재실행하지 않았으며, R1 판정의 81 통과 기록과 정적 계약 확인을 구분했다. 패치 스크립트·build·commit·push는 실행하지 않았다. 이 보고서 외 파일은 작성·수정하지 않았다.
