## R2-L01 — ID 계약 불일치와 무응답 폐기가 이벤트 누락을 숨김

- **심각도:** Low, 신규, 미해결.
- **위치:** `app/src/domain/events.ts:32–46,161–164,181–201`, `app/src/store/useAppStore.ts:78–79,295–297`. 관련 연결 경계: `app/src/data/validate.ts:145,182`의 문자열 ID 검사.
- **문제:** AppEventInput의 screen/placeId/phraseId는 일반 string인데 런타임은 64자 이하 소문자 ID만 허용한다. 콘텐츠 검증은 같은 형식을 강제하지 않는다. logEvent는 성공·실패 모두 undefined를 반환하고, 선택 ID 하나가 틀려도 이벤트 전체를 버린다. 따라서 타입 검사와 콘텐츠 검증을 통과한 호출이 집계에서 빠져도 호출자가 알 수 없다.
- **재현 1:** 실제 downtown JSON의 첫 문장 ID만 `SSD-PHRASE`로 바꾼 복사본은 `validateContent` 오류가 0개였다. 해당 ID의 phrase_play는 toAppEvent에서 폐기된다. 현재 배포 데이터가 잘못됐다는 뜻은 아니며, 두 모듈의 계약이 다르다는 재현이다.
- **재현 2:** 0분 ssd place_view → 20분 `screen_view(screen:'/order')` → 40분 gwc place_view를 호출하면 중간 호출은 undefined를 반환하며 사라진다. 기록에는 40분 간격만 남아 추가 방문 비율이 `{numerator:0, denominator:1, rate:0}`이 된다. 중간 screen이 올바른 `order`였다면 두 간격이 각 20분이므로 같은 세션이고 비율은 1이다. 누락은 화면 횟수뿐 아니라 세션 분할과 분자에도 영향을 준다.
- **판정 이유:** 잘못된 입력을 저장하지 않고 사용자 흐름을 중단하지 않는 정책 자체는 타당하며 R1 판정 지시대로 구현됐다. 다만 조용한 실패를 유일한 인터페이스로 두는 것은 Phase 2 연결 오류를 숨긴다. 현재 실제 화면의 logEvent 소비자가 없고 현 데이터 ID는 형식에 맞으므로 Medium 회귀로 판단하지 않는다.
- **권장 수정:** 폐기 정책은 유지하되 logEvent가 boolean 또는 입력값을 포함하지 않는 실패 사유 코드를 반환하도록 한다. 화면 키를 고정된 union/상수로 정의하고 콘텐츠 ID 검증과 이벤트 ID 형식을 공유한다. 개발 진단을 추가한다면 원본 event/ID/인식 문자열을 콘솔에 출력하지 말고 이벤트 종류·실패 필드명·사유 코드만 사용한다. 실제 콘텐츠의 모든 장소/문장 ID와 화면 이벤트 생성기가 정제를 통과하는 계약 테스트, 잘못된 ID의 실패 반환 테스트를 추가한다. 데이터를 소문자로 임의 변환하거나 경로를 그대로 허용하는 방식은 ID 충돌·원문 저장 위험 때문에 권하지 않는다.

ID_PATTERN은 형식 검사이며 데이터 목록의 허용 ID 검사나 개인정보 판별기는 아니다. 예를 들어 `phraseId:'hello'`는 현재 통과한다. 따라서 M-01의 추가 필드 제거는 해소됐지만 ‘어떤 인식 원문도 ID 자리에 저장될 수 없다’는 보장은 아니다. Phase 2는 실제 콘텐츠 ID와 고정 화면 키만 넘겨야 한다. 이 주의점은 R2-L01의 계약 보완에 포함하며 별도 건수로 중복 집계하지 않는다.

## takeout 및 지표 설계 판단

**단일 boolean 유지에 동의한다.** 활성 주문이 하나이고 장소 전환 시 기존 주문을 비우므로 장소별 포장 맵은 요구되지 않는다. 목업의 장소별 선택 기억과 ssd 기본 true는 필수 요구가 아니며, 새 장소에서는 false로 시작하는 A-1 반영도 일관된다. Phase 2는 목업의 `takeout[pid]`를 이식하지 말고 현재 store 값과 해당 장소의 effectiveTakeout 결과를 사용해야 한다. 장소별 취향 기억을 향후 요구한다면 별도 모델로 검토하면 된다.

currentPlaceId 장소만 cart 수정 가능하게 한 정책과 anchorPlaceId 인자화에도 계속 동의한다. Phase 2는 전환 확인이 끝나기 전에 새 장소 주문을 수정하지 않아야 하고, 성심당 리포트에는 `ssd`를 전달해야 한다. 현재 6종 이벤트, 500건 상한, 30분 이상 간격 분리, 세션 단위 분자·분모와 빈 분모 null 계산은 유지됐고 관련 테스트도 통과했다.

**최종 집계:** R1 미해결 0건, 신규 Low 1건(R2-L01), 총 미해결 **H0 / M0 / L1**. 주요 수정은 승인 가능하나 미해결 0으로 표기하려면 R2-L01을 반영하거나 Phase 2 계약 보완으로 명시적으로 이관해야 한다. 전체 타입 검사 오류는 별도로 coordinator가 통합 확인해야 한다.
