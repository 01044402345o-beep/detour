## M-01 — 타당(잠재), Medium → Low

**사실 확인**
- `hours.ts:56-59`는 현재 달력 요일(`day`)로만 휴무를 검사한 뒤 자정 넘김 구간을 `minutes >= start || minutes < end`로 판단합니다. `18:00–02:00`, `closedOn: 'mon'`이면 다음 두 시각이 반대로 계산됩니다.
  - 화요일 01:00(월요일 영업의 연장): `open`
  - 월요일 01:00(일요일 영업의 연장): `closed`
- 이 계산은 Codex가 실제로 실행해 확인한 결과와 같습니다. `hours.test.ts`는 자정 넘김과 휴무일을 따로따로만 검사합니다.

**하향 이유**: 위 표대로 현재 데이터에는 이 조합이 없어 사용자에게 보이는 오류가 0건입니다. 앞으로 데이터가 바뀌면 나타날 수 있는 잠재 결함이고, 영업 상태 자체도 "참고값"(F-04)이므로 Low가 맞습니다. 수정 비용이 작으므로 T2.3 안에서 고치기를 권장합니다.

**수정 지침 (`screens/Place/hours.ts`·`hours.test.ts`)**
1. 정책을 "휴무 요일은 그날 **시작하는** 영업이 없다는 뜻"으로 정하고 `openStatus` 주석에 적습니다.
2. 계산을 다음과 같이 나눕니다.
   - 일반 구간(`end > start`): 당일이 휴무면 `closed`, 아니면 `start ≤ m < end`.
   - 자정 넘김 구간: `m >= start`이면 **당일** 휴무 여부를 보고, `m < end`이면 **전날**(`DAYS[(idx + 6) % 7]`) 휴무 여부를 봅니다. 둘 다 아니면 `closed`.
3. 테스트를 추가합니다(`18:00–02:00`, `closedOn: 'mon'`).
   - 월 01:00 → open (일요일 영업의 연장)
   - 월 19:00 → closed
   - 화 01:00 → closed
   - 화 01:59 → closed, 화 02:00 → closed
   - 화 18:00 → open
   - 일 → 월로 넘어가는 경계 01:59 → open, 02:00 → closed
4. 회귀 방지로 `00:00–24:00` → 항상 open과, 같은 날 끝나는 휴무 케이스를 계속 확인합니다.

## L-01 — 타당(현재 도달 경로 없음), Low 유지

**사실 확인**
- `PlaceScreen`의 key는 `place.id`(`index.tsx:42`)이고, `tab`은 `useState` 초기화에서만 `location.state`를 읽습니다(`:69`).
- 같은 `/place/:id`에서 새 history entry로 `{ tab }`을 넘기면 화면이 다시 마운트되지 않아 이전 탭이 남습니다.
- 현재 `{ tab: 'menu' }`를 넘기는 곳은 `Reply/index.tsx:70` 하나뿐이고, 다른 화면(S09)에서 오므로 항상 다시 마운트됩니다. Place 화면 안에서 자기 자신으로 이동하는 코드도 없습니다. 지금 UI로는 이 결함에 도달할 수 없습니다.

**수정 지침 (선택이 아니라 반영 권장. 비용이 작고, 앞으로 경로가 추가될 때를 막아 줍니다)**
1. `PlaceScreen`에서 `useLocation()`을 읽고 `<PlaceView key={\`${place.id}:${location.key}\`} …/>`로 바꿉니다. 탭을 누르는 동작은 navigation이 아니므로 다시 초기화되지 않습니다. 새 entry일 때만 탭·시트·보류 메뉴가 초기화됩니다. `place_view` 기록은 이미 `location.key`당 1회라 영향이 없습니다.
2. 테스트를 추가합니다. `/place/ssd`에서 이용 방법 탭을 누른 뒤 같은 경로로 `{ tab: 'menu' }`를 넘겨 navigate하면 메뉴 탭이 선택되는지, 탭을 직접 누를 때는 초기화되지 않는지 확인합니다.
