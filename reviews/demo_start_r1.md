# 녹화용 대전역 출발 고정 검토 R1

검토일: 2026-11-26. 판정: **H 0 / M 0 / L 2 — 현재 두 코스 데이터와 녹화 후 복구 전제에서는 배포를 막는 결함 없음.**

## 지적

### L-01 — 고정 출발지가 코스 배열의 첫 항목에 종속됨

- 위치: `app/src/ui/map/externalMap.ts:9,20`, `app/src/data/index.ts:42–45,67–74`, `app/src/ui/map/externalMap.test.ts:37`.
- 근거: `DEMO_START = courses[0].start`라서 코스 순서를 바꾸거나 다른 출발지 코스를 첫 항목에 넣으면 고정 출발지도 바뀐다. 현재 두 코스는 모두 동일한 대전역 좌표이고, 테스트가 한국어 이름·좌표·비어 있지 않은 배열 및 리터럴 URL을 확인하므로 현재 오작동은 아니다. 빈 배열에서는 모듈 평가가 실패하지만, 기존 data 모듈도 `bundles[0].course`를 즉시 참조하므로 이번 변경만의 새로운 빈 배열 장애로 분류하지 않았다.
- 영향: 독립적인 URL 유틸리티가 콘텐츠·경로 JSON 네 개와 검증 코드에 런타임으로 의존한다. 향후 별도 소비자나 데이터 로딩 분리를 만들 때 부담이 된다. 현재 화면에서 실제 번들 크기 증가나 초기 로딩 회귀가 확인된 것은 아니다.
- 수정안: 임시 변경의 목적에 맞게 `DEMO_START`를 `{ nameKo: '대전역', geo: { lng: 127.4325, lat: 36.3315 } }`인 독립 상수로 두고, 데이터와의 일치 여부는 테스트에서 검증한다. 이를 통해 첫 코스 의존과 런타임 data import를 함께 제거할 수 있다. 이번 단기 녹화 배포의 필수 수정은 아니다.

### L-02 — 화면 안내가 대전역 고정을 알리지 않으며 앱 직접 열기를 단정함

- 위치: `app/src/screens/Course/index.tsx:377`, `app/src/screens/Place/InfoTabs.tsx:62`, `app/src/i18n/en.json:105,138` 및 `ja.json`, `zh.json`의 같은 키, `DESIGN.md:110`, `prd.md:170`.
- 근거: `course.dirTo`, `place.dirHint`는 네이버 지도 앱에서 길찾기가 열린다고 안내하며 출발지 고정은 표시하지 않는다. 제공된 브라우저 확인 결과는 모바일에서 빠른길찾기 웹 페이지와 별도의 '지도앱으로 보기'가 나온다는 것이다. 앱 직접 열기를 단정하는 문구는 변경 전부터 있던 문제이며, 이번에 처음 생긴 회귀는 아니다. 다만 녹화에서도 화면 설명과 실제 열린 화면이 어긋날 수 있고, 2번 이후 정류장이나 장소 상세 링크도 모두 대전역 출발이라는 사실은 코드 주석에만 있다.
- 수정안: 필요하면 임시 안내를 세 언어로 '대전역에서 선택한 장소까지 네이버 도보 길찾기'로 명시하고, 앱 관련 문구는 '네이버 지도에서 열기'처럼 웹에서도 맞도록 조정한다. 화면을 그대로 녹화하려는 의도라면 알려진 제한으로 수용하고 녹화 후 즉시 복구한다. 영구 PRD를 임시 동작 전체로 바꿀 필요는 없으며, 운영 기록에만 임시 상태를 남겨도 된다.

## 확인 결과

1. **URL 및 호출처:** 실제 호출은 Course의 `naverWalkUrl(nextPlace)`(`index.tsx:368`)와 Place 이용 방법 탭의 `naverWalkUrl(place)`(`InfoTabs.tsx:40`) 두 곳이다. Course의 행선지 선택·다음 정류장 로직은 변경되지 않았으며 도착지는 선택한 장소다. `point()`는 경도, 위도 순서로 소수 여섯 자리 반올림 후 문자열화하고 한국어 이름에 `encodeURIComponent`를 적용한다. 출발은 `127.4325,36.3315,대전역,,`, 경유는 `-`, 모드는 `walk`다. Google Maps는 기존 위도, 경도 검색을 유지한다. 새 경로 문자열 조립에서 결함을 발견하지 못했다.
2. **의존성과 코드 분할:** `externalMap → data/index → JSON, validate, route → types` 경로에서 ui/map으로 돌아오는 import가 없으므로 순환 참조를 발견하지 못했다. data 모듈은 Leaflet을 import하지 않는다. Place는 externalMap을 직접 import하므로 지도 컴포넌트/Leaflet을 끌어오지 않으려는 의도는 유지된다. Course와 Place는 변경 전부터 data를 런타임 import하고 라우터는 각 화면을 lazy import하므로 이번 연결만으로 새로운 초기 데이터 로딩이 생겼다고 볼 근거는 없다. 번들 산출물 생성은 금지 범위이므로 빌드 크기 전후 실측은 하지 않았다.
3. **안내 검색:** app/src, DESIGN, PRD, README, task 문서에서 현재 사용자 안내로 '네이버가 출발지를 물어봄/현재 위치에서 시작'을 약속하는 문구는 발견하지 못했다. `externalMap.ts:5`의 출발지 비움 서술은 복구 대상 버전을 설명하므로 오류가 아니다. 화면의 실제 안내 제한은 L-02와 같다.
4. **복구 기준:** HEAD와 `pre-demo-start^{commit}`는 모두 `c37240333a9d5eb9c645776cf66b9e4995618e33`이다. `pre-demo-start`는 annotated tag이므로 태그 자체의 객체 ID `a970be81…`와 커밋 ID가 다른 것은 정상이다. `git diff pre-demo-start --stat`에는 지정된 두 파일만 있고 32줄 추가/10줄 삭제이며 staged 변경은 없다. 코드만 원복하는 두 파일 단위 복구가 가능하다. 실제 배포 이후에는 복구 커밋과 재배포가 필요하며, 이후 다른 작업이 추가되면 태그 전체로 되돌리기 전에 그 변경의 보존 여부를 확인해야 한다.
5. **기타 작업트리 파일:** 검토 시작 시부터 `app/tsconfig.tsbuildinfo`, `deck/index_before_T6.15.html`, 여러 reviews 문서가 untracked 상태다. 이번 tracked diff에는 섞이지 않았지만 일괄 add 대상으로 삼으면 혼입될 수 있다. 변경 두 파일만 명시적으로 스테이징하면 된다. 본 검토는 보고서 외 소스 파일을 수정하지 않았다.
6. **테스트:** `app`에서 `npx --no-install vitest run src/ui/map src/screens/Course src/screens/Place --no-cache --configLoader runner` 실행, **12개 파일 / 233개 테스트 통과**. 테스트 캐시와 설정 번들 생성을 피하는 옵션을 사용했다. externalMap 단위 테스트는 고정 출발 URL 전체, 좌표 순서/반올림, 슬래시 포함 이름 인코딩, Google 링크, 모든 장소와 모든 코스의 출발지 일치를 확인한다. 화면 테스트는 Course의 행선지 변경/다음 정류장 및 Place의 링크 연결을 확인한다. 화면 테스트의 기대값이 같은 URL 함수에 의존하지만 별도 단위 테스트에 독립적인 리터럴 기대값이 있으므로 이번 변경에 필요한 검증은 충분하다.

## 검증 한계

네이버 실서비스의 PC·모바일 동작은 작업 지시의 Claude/Playwright 확인 결과를 근거로 삼았으며 이 검토에서 재실행하지 않았다. 실제 휴대폰 브라우저와 네이버 앱 설치 여부에 따른 전환은 직접 검증하지 않았다. Git 쓰기·커밋·배포·원복을 실행하지 않았다.
