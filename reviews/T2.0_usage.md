## 화면 task 사용 안내
- import: `import { Button, ListenButton, Pronunciation, Sheet, TopBar, useToast, ... } from '../../ui'`, 경로: `import { PATHS, placePath } from '../../router/routes'`.
- screen_view는 라우터가 자동 기록 → 화면은 기록하지 말 것(place_view·phrase_play 등만 직접).
- 탭바는 라우트 표(tabBar)로 앱 틀이 붙임 — 화면에서 넣지 말 것.
- 화면 루트의 `data-testid="screen-<key>"`는 E2E가 쓰므로 **필수 유지** (`<section className="screen" data-testid="screen-<key>">`).
- `router/*.test.*`와 `App.test.tsx`는 T2.0 소유. 라우터 테스트는 화면을 mock하므로 화면 내용과 무관합니다. 화면 task는 자기 `screens/<이름>/` 안의 테스트만 추가하고 라우터 테스트를 고치지 않습니다.
- 장소 화면처럼 같은 라우트에서 `:id`만 바뀌는 화면은 콘텐츠 루트에 `key={id}`를 줘서 듣기 버튼 등이 다시 마운트되게 할 것(이전 장소 발화가 이어지지 않게).
- 연습·직원 이동: `navigate(PATHS.practice, { state: phraseInput('order') })` / `phraseInput('phrase', phraseId)`. 타입은 `{ src: 'order' } | { src: 'phrase'; phraseId: string }`이고 phraseInput은 값을 바꾸지 않습니다.
- 받는 쪽은 `parsePhraseInput(useLocation().state)` 한 곳에서 검증(phraseId는 `isValidId` 형식). null이면 받는 화면이 처리(직접 진입·새로고침·잘못된 ID). 실제 문장이 데이터에 있는지는 받는 화면이 `downtown.json`에서 찾아 확인하고, 없으면 같은 null 처리. 새로고침해도 history state가 남을 수 있으니 'state 없음 = 새로고침'으로 가정하지 말 것.
- ListenButton: `variant` 'round'(목업 .playb) | 'pill'(목업 .ctrl, 문구 포함) | 'bare'(단어 칩: children·label 지정), `rate={0.75}` 천천히, `onPlay`에서 phrase_play 기록, 한 화면에 여러 개면 `showNotice`는 하나만 true. 테스트에서는 `tts` prop으로 가짜 주입.
- Pronunciation: `<Pronunciation roman={x.roman} kana={x.kana} />`(현재 언어 자동), 문자열은 `pickPronunciation(lang, x)`.
- Sheet: `<Sheet open onClose title={...}>` 또는 제목 없이 `<Sheet open onClose label={t(...)}>` — **title 또는 label 중 하나 필수**(타입이 강제, dialog 이름). #app-overlay(폰 프레임 안)에 포털, Esc(맨 위 시트만)·바탕·닫기 버튼으로 닫힘, 열릴 때 시트로 포커스·닫히면 복귀, Tab/Shift+Tab은 시트 안에서 순환.
- Sheet가 열린 동안 배경(main.app-view·탭바)은 자동으로 `inert`. 화면 task가 배경 요소에 `inert`를 직접 걸지 말 것. 시트는 한 번에 하나만 엽니다(겹침 미지원). 시트 안에서 다른 시트를 열지 말고, 이어지는 확인이 필요하면 지금 시트의 내용을 바꾸거나 닫은 뒤 여세요. 개발 모드에서 두 번째 시트가 열리면 콘솔 경고가 나옵니다. (T2.3 장소 전환 확인 시트와 T2.6 ReportSheet는 동시에 열리지 않게)
- Sheet Tab 순환 후보: tabIndex ≥ 0, `:disabled` 아님(disabled fieldset 포함), hidden·inert 조상 없음, 계산 스타일 display:none·visibility:hidden 아님. 조건부로 숨기는 컨트롤은 `hidden`·`display:none`·`disabled` 중 하나로 숨기면 순환에서 빠집니다. jsdom 단위 테스트는 인라인 스타일로 검증했고, 클래스로 숨긴 실제 브라우저 경우는 Phase 2 E2E에서 ReportSheet로 1회 확인. ui/ReportSheet(T2.6)는 이걸 쓰면 됨.
- Toast: `const toast = useToast(); toast(t('common.comingSoon'))`, 2.4초.
- TopBar: `title`, `backTo`(바로 열기 시 갈 곳), `onBack`, `right`.
- 새 색 조합·누를 요소 클래스를 ui.css에 추가하면 ui/a11y.ts 표에 등록(테스트가 강제). 화면 전용 CSS의 작은 버튼(목업 .qty 30px, .addb 36px 등)은 44px 이상으로 — 공용 검사는 ui.css만 보므로 화면 task가 책임.
- `router/screens.test.ts`는 화면 모듈 default export가 함수인지 확인합니다. 화면을 `memo`/`forwardRef`로 감싸 객체가 되면 coordinator와 조율하세요.
- i18n: `nav.*`, `common.back/close`, `audio.*` 키를 사용. 사전 변경 없음.
