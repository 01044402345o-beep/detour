## 2. R1 해결 여부

### M-01 — 해결

- `staffContent.ts:114`의 계산은 `max(56, min(단계, 낱말이 들어가는 크기))`입니다. 56px 하한을 우선하며, `staffSizeControls`는 실제 표시 크기가 다른 가장 가까운 단계만 제공합니다.
- `index.tsx:57`은 현재 문장의 Text 노드에서 일반 공백으로 나눈 낱말별 Range 폭을 합산하고 현재 font-size로 나눕니다. NBSP로 묶은 수량·단위는 하나로 측정합니다. 현재 JSX는 실제로 단일 Text 노드를 렌더하므로 전제와 맞습니다. 조각 합산은 줄이 나뉜 긴 낱말에도 적용되며, 1% 여유와 0.1px 내림을 적용합니다.
- `index.tsx:103`에서 첫 layout effect, 문장 변경, ResizeObserver, 글꼴 `loadingdone`에 재측정합니다. 단순 단계 변경은 문장 박스 높이가 달라질 때 observer가 다시 읽습니다. 박스 치수가 그대로인 경우에도 현재 글꼴·em 자간의 낱말 폭 비율이 유지되므로 단계마다 별도 effect를 반드시 실행할 필요는 없습니다. 0.01em 미만 변화 억제는 반올림으로 인한 반복 갱신을 줄입니다.
- CSS의 `keep-all`과 `overflow-wrap:anywhere`는 56px로도 들어가지 않는 낱말만 내부 줄바꿈을 허용합니다. DESIGN.md:47도 이 하한·버튼 비활성·낱말 내부 줄바꿈 예외를 명시하여 R1의 기준 충돌을 해소했습니다.

## 3. 접근성·레이아웃·이벤트 회귀

- 크기 버튼은 실제 HTML `disabled`와 번역된 `aria-label`, 이름 있는 group을 사용합니다. R2 Edge 접근성 스냅샷에서도 Bigger 또는 양쪽 버튼에 `[disabled]`가 표시됐습니다. 별도 aria-disabled 누락 문제는 없습니다.
- 360 → 430 → 360 리사이즈와 크기 변경에서 가로 넘침·pageerror가 없었습니다. 상단 조작 띠 높이는 모두 66px로 일정했습니다. 글자 확대에 따른 문장 높이 증가는 정상 재배치입니다. 각 폭에서 `loadingdone` 이벤트 후 50ms 간격 8회 표본의 크기·높이·버튼 상태가 같아 지속 진동은 관찰되지 않았습니다.
- `ResizeObserver.disconnect()`와 `fonts.removeEventListener('loadingdone', read)`가 effect 정리에 있습니다. 브라우저 계측에서도 두 주문 각각 등록/해제 1/1, 직원 문장 observe/disconnect 1/1을 확인했습니다. 닫은 뒤 남는 직원 화면 구독은 없었습니다.
- 비활성 버튼이 옅은 배경만으로 구분되는 점은 수정 보고서에 공개된 기존 표현입니다. 시각적 개선 여지는 있으나 상태가 접근성 트리에서 누락되거나 조작이 계속 허용되는 회귀는 아니므로 새 결함으로 재등록하지 않습니다.
- 글꼴 로드의 실제 지연 타이밍·모든 OS·모든 브라우저까지 검증한 결과는 아닙니다. R2의 인위적 loadingdone 이벤트 확인은 이벤트 경로와 안정성 검증이며 실제 글꼴 전환 검증을 대체하지 않습니다. 글꼴 차단 전후 근거는 R1 수정 자료를 함께 사용했습니다.
