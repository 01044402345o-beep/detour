## M-01 — TTS와 STT를 동시에 실행할 수 있어 정답 음성이 인식에 섞임

- **위치:** `app/src/screens/Practice/index.tsx:146–157, 199–229`.
- **문제:** 문장/느린 듣기/단어 칩을 재생한 직후 마이크를 켜도 기존 TTS를 취소하지 않는다. 반대로 requesting/listening/processing 중에도 모든 ListenButton이 활성화되어 있다. 스피커로 정답을 듣다가 바로 연습하는 정상 사용 순서에서 사용자 발화와 앱의 정답 음성이 겹칠 수 있고, 인식 결과와 practice_done 점수가 사용자 연습을 제대로 나타내지 못한다. 브라우저에 따라 동시 음성 서비스 충돌로 실패할 가능성도 있다.
- **근거:** `onMic`와 `retry`는 STT start만 호출한다. ListenButton의 취소 계약은 화면 이탈·다른 TTS 선점에 관한 것으로, 같은 화면의 STT 시작을 감지하지 않는다. 버튼에 active에 따른 차단도 없다. F-08의 말하기 연습과 F-09의 인식 비교를 연결하는 화면에서 두 음성 경로의 상호 배제가 빠졌다. 기존 테스트는 듣기와 인식을 각각 검증하지만 이 순서를 검사하지 않는다.
- **권장 수정안:** 화면에서 실제 사용하는 TTS 인스턴스를 공유하여 STT 시작·재시도 전에 cancel하고, 인식이 활성인 동안 듣기를 막거나 듣기 시작 전에 인식을 명시적으로 취소한다. T2.4 안에서 처리할 수 있는 래퍼/fieldset 등을 우선 사용하고, 공용 ListenButton API 변경이 필요하면 0.2절대로 coordinator와 조율한다. `듣기 → 마이크`, `listening → 단어/느린 듣기`, `실패 → 듣기 → 재시도`의 상호 배제와 선점된 재생 표시 해제를 컴포넌트 테스트로 확인한다.

## L-01 — 학습 단위와 결과 단위가 달라 수량 표현 피드백이 분절됨

- **위치:** `app/src/screens/Result/resultState.ts:26–27`, `app/src/screens/Result/index.tsx:96–116` (대조: Practice의 `item.words`, `domain/scoring.ts`의 공백 토큰화).
- **문제:** S06은 `두 개`, `한 개`를 각각 하나의 듣기 칩으로 가르치지만 S07은 채점 토큰을 그대로 표시하여 `두`/`개`, `한`/`개`로 쪼갠다. 수량 표현 일부가 불일치하면 팁도 `개`만 지목할 수 있어 사용자가 앞 화면의 어느 칩을 다시 연습할지 연결하기 어렵다. 결과 칩이 늘어나 작은 화면의 피드백과 버튼도 아래로 밀린다.
- **근거:** 제공 캡처의 App S07에서 분할을 직접 확인했다. 목업은 `ph.w`를 결과 칩으로 사용하고 S06과 같은 `두 개` 단위를 유지한다. 총점 계산 오류는 아니며, F-09가 공백 토큰화 자체를 금지하지 않으므로 Low로 분류한다. 문제는 화면 사이 학습 단위와 약한 단어 안내의 일관성이다.
- **권장 수정안:** 채점 알고리즘·총점은 유지하고 T2.4 결과 변환에서 목표 문장의 토큰 위치를 `item.words`의 학습 단위로 매핑한다. 한 단위 안에 불일치가 있으면 그 단위를 불일치로 표시하고 weakestIndex도 같은 표시 단위로 옮긴다. 중복된 `주세요`/`개`가 있으므로 텍스트 검색만으로 병합하지 말고 순서·범위를 사용한다. `두 개 → 두`와 `두 개 → 세 개`, 중복 수량 및 완전 일치를 검증한다. 공용 scoring 변경은 이 task에서 하지 않는다.

## L-02 — 한국어가 포함된 팁과 칩 접근성 이름에 언어 구분이 소실됨

- **위치:** `app/src/screens/Result/index.tsx:116`, `app/src/screens/Practice/index.tsx:223–227`.
- **문제:** 결과 칩 자체는 `lang="ko"`이지만 팁은 사용자 언어 번역 문자열 안에 `weak.ko`를 삽입한 단일 span이다. 따라서 같은 한국어 단어가 팁에서는 EN/JA/ZH 문서 언어를 상속한다. S06 칩도 자식 span에는 ko가 있지만 버튼의 단일 `aria-label`이 자식 이름을 덮어써, 낭독 이름의 한국어 부분에는 언어 경계가 없다. 한국어를 배우려는 화면에서 보조기술의 발음 전환에 필요한 정보가 빠진다.
- **근거:** 결과의 sr-only Matched/Not matched는 사용자 언어로 올바르게 분리했지만 위 두 경로는 그렇지 않다. 기존 테스트는 팁 문자열과 accessible name을 비교할 뿐 한국어 삽입 부분의 lang을 확인하지 않는다. 낭독기의 실제 발음은 기기별 차이가 있으므로 실측 오독을 단정하지 않는다.
- **권장 수정안:** 팁의 번역 템플릿을 유지하면서 `{word}` 부분을 `<span lang="ko">` 노드로 렌더링한다. 칩은 한국어·번역 각각의 언어가 보존되는 콘텐츠/라벨 연결 방식을 사용한다. 공용 ListenButton의 이름 API를 바꿔야 하면 coordinator와 조율한다. DOM 언어 구조 검사 후 T4.3 TalkBack에서 단어 칩·팁 낭독을 확인한다.

## 나머지 중점 항목 확인

- **STT 상태·이탈:** requesting 15초, listening/processing 각 8초와 실패 재시도/직원 경로가 연결되어 있다. effect cleanup에서 dispose하며, 어댑터가 기존 핸들러·타이머를 정리하고 시도 번호로 늦은 콜백을 차단한다. start의 ACTIVE 가드가 중복 세션을 막는다. 화면의 빠른 연속 탭/이탈 뒤 캡처한 늦은 콜백에 대한 통합 테스트는 부족하지만, 읽은 코드에서 별도 중복 인식 결함은 확인하지 못했다. 재검증 시 해당 순서를 추가하면 좋다.
- **미지원·사전 안내:** unsupported 마이크 disabled, 재시도 없음, 직원 경로 제공. 마이크 사용 전부터 3개 언어 음성 처리 안내가 노출되고 aria-describedby로 연결된다. denied 및 실패 상태도 안내된다.
- **원문·empty:** result 콜백에서 reset한 뒤 채점하며, router state는 목표 단어·일치 여부·점수만 담고 transcript/heard를 제외한다. 이벤트/DEV 경고에 들어가는 것은 ID·점수뿐이다. 정규화 후 empty는 결과 화면/0점 대신 재시도로 안내한다. 목표 단어를 담는 것을 인식 원문 저장으로 보지 않았다.
- **85점 분기:** 85 이상만 closeMatch 문구를 보이고 미만에는 거의 다 왔어요와 노란 링을 사용한다. 항상 인식 일치도 설명 및 발음 등급이 아니라는 안내를 표시하므로 목업의 직원 이해 보장을 제거한 것은 PRD 우선 원칙에 맞다. 84/85 경계 테스트는 추가 권장이나 현재 비교식 자체는 맞다.
- **withOrder:** parsePhraseInput을 재사용하고 내부 optional 플래그만 확장한다. 직원 화면에는 staffInput으로 기본 계약만 내보내며, 주문이 사라지면 일반 문장 목록으로 처리한다. 공용 타입/파서 수정이나 공용 계약 충돌은 확인하지 못했다.
- **하드코딩·접근성:** 사용자 문구는 i18n, 문장은 데이터/주문 생성 결과를 사용한다. 85·링 치수·파형·색 등은 디자인/분기 상수로, 문구 하드코딩과 구별했다. 일치 여부 sr-only, 목표 문장/결과 단어의 lang=ko, 44px 버튼 최소 크기, reduced-motion 대응을 확인했다. 제공 캡처는 주로 영어·일부 상태만 보여 주므로 세 언어/뷰포트 전체의 실제 레이아웃 통과 근거로 확대하지 않는다.
