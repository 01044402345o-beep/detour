## R2-L-01 — 빈 음성 목록에서 제거된 voice와 ready 상태가 영구 유지됨

- **분류:** Low, 기존 M-03의 미해결 잔여 분기. 독립 신규 건으로 중복 집계하지 않음.
- **위치:** `app/src/speech/tts.ts:83–90,123–127`, `app/src/speech/tts.test.ts:160`.
- **문제:** `refreshVoice()`는 목록 길이가 0이면 즉시 반환합니다. 이전 state가 ready라면 뒤의 `init()`도 즉시 ready를 반환하여 2초 재탐색을 시작하지 않습니다. `speak()`도 기존 voice를 유지합니다. 따라서 빈 목록이 계속되어도 영원히 ready이고 더 이상 목록에 없는 음성을 새 utterance에 지정합니다. 코드에 주석으로 적힌 “일시적” 여부를 판별하거나 보존 시간을 제한하는 로직이 없습니다.
- **근거:** 재현 순서는 `[ko] → await init() → voices=[] 및 voiceschanged → await init() → speak()`입니다. 현재 코드 실행 결과는 `{"initAfterAllVoicesRemoved":"ready","state":"ready","staleVoice":"ko"}`였습니다. 새 테스트도 `[ko]→[]`에서 기존 voice 유지 자체를 기대하며 장기 빈 목록을 구별하지 않습니다. API 계약상 빈 목록은 목록이 아직 알려지지 않은 경우와 사용 가능한 음성이 없는 경우 모두 가능하며, voiceschanged에는 설치·제거도 포함됩니다. [Web Speech getVoices·voiceschanged 계약](https://webaudio.github.io/web-speech-api/#tts-methods)
- **영향/심각도:** 모든 음성이 사라지거나 음성 서비스가 목록을 비우는 경우, F-07의 음성 없음 안내가 잘못되고 오래된 선택 음성을 계속 사용합니다. 한국어가 뒤늦게 추가되는 주요 경로는 이미 복구되었고 제거 상황의 빈도도 낮아 Medium 대신 Low입니다. 실제 특정 기기에서 항상 발화 실패한다고 단정하지 않습니다.
- **권장 수정안:** 잠시 빈 목록을 보존하려면 최대 2초의 유한 재확인 후에도 비어 있을 때 voice를 null, state를 no-korean-voice로 정리합니다. `init()`이 과거 ready만 보고 이 재확인을 건너뛰지 않게 해야 합니다. 또는 빈 목록을 즉시 최신 가용 목록으로 취급하고 기존 voice를 해제합니다. 어느 방식이든 `speak()` 안에서는 await하지 않습니다. `[ko]→[]가 계속됨`과 `일시적 []→[ko] 회복`을 분리해 테스트하고, 전자의 과거 voice가 영구 유지되지 않음을 검증합니다.
