## M-1 — 장소 알레르기 목록이 미확인 상태 없이 확정값처럼 들어 있음

**판정: 타당** / 조정 심각도: **Medium (유지)**

### 근거

- `downtown.json:61–65`(ssd)과 `:641–645`(gwc)에 `allergens`가 들어 있다. 같은 장소의 메뉴 8개는 모두 `allergenStatus: "unknown"`이다. 그런데 `Place` 타입(`types.ts:76`, `allergens?: L10n`)에는 확인 상태 필드가 없다. 그래서 화면이 이 값을 읽으면 확인된 목록과 구별할 방법이 없다.
- PRD F-04는 "알레르기 미확인은 '확인 필요'로 표시"하라고 하고, task.md T2.2(`:218`)도 같은 규칙을 둔다. T1.2 사전에는 이미 `allergyUnknown`("Allergens: to be confirmed") 키가 있다. 데이터만 확정 목록처럼 남아 있는 셈이다.
- 목업(`mockup/index.html:605`)은 `⚠ Contains: Wheat, egg, milk`를 그대로 보여 준다. 하지만 PRD와 목업이 충돌하면 PRD가 우선이다(task.md T1.2 원칙, T1.1 공기밥 단위에도 같은 원칙을 적용함). 그러니 T1.1 완료 조건 "목업 데이터와 내용 일치"는 근거가 되지 않는다.
- Medium을 유지하는 이유: 실제 가게 이름으로 알레르기 정보를 단정해서 보여 주는 건 사용자 안전과 관련된 잘못된 신호다. 특히 목록에 없는 성분은 "들어 있지 않다"는 뜻으로 읽힐 수 있다. 다만 아직 화면이 없어 실제로 사용자에게 노출되지는 않았으므로 High는 아니다.
- 루트 `note`("알레르기… 예시값. 확인 필요")는 한국어 개발용 메모라서 화면 표시 계약을 대신할 수 없다는 Codex 의견에 동의한다.

### 수정 지침 (T1.1 작성자)

1. ssd·gwc의 장소 `allergens`를 **삭제**한다. `Place.allergens`는 선택 필드라서 타입을 바꿀 필요가 없다.
   - Codex의 두 번째 안(L10n 문구를 "확인 필요" 취지로 다시 쓰기)은 쓰지 않는다. 데이터 값에 표시 문구를 섞게 되고, T1.2 `allergyUnknown` 키와 중복된다.
   - 공유 계약 `types.ts`에 `allergenStatus`를 추가하는 안도 이번에는 쓰지 않는다(T0.2 계약 변경이라 범위가 커짐).
2. `validate.ts` `checkPlace`에 회귀 규칙을 추가한다: 메뉴 중 하나라도 `allergenStatus: 'unknown'`이면 장소에 `allergens`가 있으면 안 된다. `orderable:false` 장소(메뉴 없음)에는 이 규칙을 적용하지 않는다.
3. 테스트
   - 실데이터: ssd·gwc에 `allergens`가 없음을 확인한다.
   - 검증기: unknown 메뉴가 있는 장소에 `allergens`를 넣은 fixture가 실패하는지 확인한다.
4. 다음 작업으로 넘길 것
   - **T2.2**: 장소 `allergens`가 없거나 메뉴 중 unknown이 있으면 `allergyUnknown`을 표시한다. `Contains: …`는 확정값일 때만 쓴다.
   - **T4.1**: task.md T4.1과 PRD 11장의 확인 목록에 알레르기가 빠져 있다(4장 머리말에도 없음, JSON 루트 note에만 있음). 코디네이터가 T4.1 확인 항목에 "알레르기(가게 공지·직원 확인)"를 추가할지 정해야 한다. 확인되면 T4.1a에서 `allergens`를 복원하고 `allergenStatus: 'confirmed'`로 바꾼다.

## L-1 — 발음 표기 음절 누락

**판정: 타당** / 조정 심각도: **Low (유지)**

### 근거

- `mr.roman`(`downtown.json:116`)은 `myeongnan bagete`이다. '바게트'의 마지막 음절 '트'는 `teu`라서 `bageteu`가 맞다. 같은 메뉴의 kana `バゲトゥ`는 '트'를 반영하고 있어 로마자와 가타카나도 서로 맞지 않는다.
- `gwc-4.kana`(`:840`)는 `ケサナルケヨ`이다. 로마자 `gyesanhalgeyo`는 ㅎ을 적는데 가타카나만 ㅎ을 빼서 두 표기가 어긋난다. 구어에서 ㅎ이 약해지는 현상([계사날께요])은 있지만, 표준 발음은 '할'의 ㅎ을 살린다. 같은 데이터의 `화장실 ファジャンシル`, `포장해 ポジャンヘ`도 ㅎ을 적는다.
- 된소리 정책: 데이터 전체가 된소리를 따로 적지 않는다(`maepge`/`メプケ`, task.md T1.3 표의 `タソッ ゲ`). 따라서 `ケサンハルッケヨ`는 쓰지 않고 `ケサンハルケヨ`로 맞춘다. 된소리를 적지 않은 나머지 로마자를 결함으로 보지 않는다는 Codex 판단에 동의한다.

### 수정 지침

- `mr.roman`: `myeongnan bagete` → `myeongnan bageteu`. 이 메뉴의 단어 칩과 주문 문장 로마자가 이 값을 쓰므로 함께 바뀌는지 확인한다(`roman`을 기대값으로 고정한 테스트가 있으면 갱신).
- `gwc-4.kana`: `ケサナルケヨ` → `ケサンハルケヨ`. 이 문장의 `words`에 같은 칩이 있으면 그 `kana`도 같이 고친다.
- 가타카나 근사 방식은 T4.2 원어민 검수 대상으로 남긴다.
