## M-01 — 선택 칸이 토글 아래에 생겨 토글 자체가 위로 이동함

- 위치: `app/src/screens/Course/index.tsx:338` 및 `:355`, `app/src/screens/Course/Course.css:284`, `:368`, `:403`; 관련 테스트 `Course.test.tsx:458`.
- 근거: DOM 순서는 토글 → fieldset → 길찾기 버튼 → 안내이며, dock은 일반 블록 내부 배치에 `position: sticky; bottom: 0`만 적용한다. fieldset을 토글 위로 배치하는 규칙은 없다. 따라서 펼치면 2×2 칸은 토글 **아래**에 생긴다. dock이 하단에 붙은 상태에서는 약 104px(44px 두 줄 + 6px 간격 + 10px 아래 여백) 높이가 추가되면서 토글이 그만큼 위로 이동한다. `translateY(8px)` 애니메이션은 이 배치 순서를 바꾸지 않는다.
- 영향: DESIGN.md:110의 “누르면 그 위에 … 2×2”와 요청한 아래 버튼에서 위로 올라오는 선택 팝업 동작을 충족하지 못한다. 같은 자리에서 다시 눌러 닫으려면 이동한 토글을 다시 찾아야 한다. 접힘의 위 화살표도 실제로 선택 칸이 나타나는 상대 방향과 맞지 않는다.
- 수정안: 토글을 길찾기 버튼 위의 같은 위치에 유지하고, 선택 칸이 토글 위쪽 공간에 나타나도록 배치한다. DOM 순서를 바꾸거나 위치 지정으로 구현할 때 키보드 이동 순서도 함께 점검한다. 360px 브라우저에서 펼친 칸의 아래쪽 좌표가 토글 위쪽 좌표 이하인지, 펼침 전후 토글과 길찾기 버튼의 좌표가 유지되는지 확인하는 회귀 검증을 추가한다. 현재 테스트는 보임/숨김과 문구만 검사하므로 이 문제를 잡지 못한다.

## 나머지 확인 결과

- **선택·다음 정류장:** `target = pickedIdx >= 0 ? pickedIdx : next`를 토글 값·선택 상태·네이버 링크·Google 링크·안내가 함께 사용한다. 고르기 전에는 방문 기록의 다음 정류장을 따르고, 고른 뒤에는 해당 값이 우선한다. 접기/펼치기는 방문 기록과 선택을 변경하지 않는다.
- **초기화·재진입:** `resetData`가 기록과 `walkPicks`를 비우며 실제 설정 화면 초기화는 언어 화면으로 이동한다. 코스를 다시 마운트하면 `pickOpen=false`와 1번 행선지로 시작한다. 코스 변경도 course id를 key로 사용하므로 펼침 상태가 초기화된다. 마운트된 코스에서 저장소 초기화만 직접 호출하면 펼침은 유지되지만, 실제 초기화 경로는 화면을 떠나므로 사용자 흐름의 결함으로 보지 않았다.
- **펼친 상태의 길찾기:** 링크는 선택된 `nextPlace`를 그대로 사용하고 새 창으로 연다. 원래 코스의 펼침 상태를 유지하는 동작이며 요구에 자동 접힘 조건은 없다.
- **접근 가능한 이름:** 토글의 실제 텍스트가 제목 + 번호 + 전체 장소 이름을 제공한다. 말줄임은 시각 표현이며 DOM 텍스트를 줄이지 않는다. 걷기·화살표 SVG는 `aria-hidden=true`다.
- **hidden·그룹 이름:** `aria-controls` 대상은 숨겨져 있어도 DOM에 같은 id로 존재한다. `hidden`과 명시적인 `display:none`으로 접힌 라디오가 접근성 트리와 탭 이동에서 빠진다. 펼치면 `sr-only` legend가 fieldset 그룹 이름을 제공하며 기존 role/name 테스트가 이를 확인한다.
- **초점:** 현재 구조는 키보드로 토글을 열 때 초점이 토글에 남고 다음 Tab으로 선택된 라디오에 접근할 수 있는 일반적인 펼침 구조다. 모달이 아니므로 자동 초점 이동 자체가 필수는 아니다. M-01 수정 후에는 시각 순서와 Tab/Shift+Tab 순서를 다시 확인해야 한다.
- **크기·대비:** 토글과 라디오의 최소 높이는 44px이다. 주요 글자와 화살표의 `--mute`, `--ink`, 파란 아이콘은 흰색/연파랑 바탕에서 식별 가능한 대비를 갖는다. 옅은 외곽선만으로 조작 여부를 전달하지 않고 텍스트·아이콘·초점 윤곽선을 함께 사용한다.
- **폭·높이:** 360px에서 dock 좌우 16px를 제외한 328px 안에 토글이 들어가며, 텍스트 영역의 `min-width:0`과 현재 값 말줄임, 2열의 `minmax(0,1fr)`가 가로 넘침을 방지하는 구조다. 접힘은 기존 상시 2×2보다 높이를 줄인다. 펼침 시 높이와 토글 이동 문제는 M-01에 기재했다. 실제 360px·3개 언어 렌더링은 이번 검토에서 측정하지 않았다.
- **애니메이션:** `--dur=200ms`, `hidden` 해제 시 fieldset의 상승/등장 애니메이션이 적용된다. 닫기는 즉시 숨김이며, 명시된 구현 요구에는 닫기 애니메이션이 없다. 움직임 줄이기에서는 지역 규칙과 전역 `!important` 규칙으로 애니메이션·화살표 전환을 끈다.
- **테스트 범위:** 두 코스의 현재 값 갱신, 접힘/펼침, 링크, 상세 왕복 선택 유지, 초기화, 그룹·라디오 이름은 코드상 검사한다. 추가된 CSS 문자열 검사는 실제 레이아웃·키보드 초점·미디어 설정의 렌더링을 입증하지 못한다. M-01 회귀 검증과 함께 토글의 `toHaveAccessibleName`, 키보드 열기 → 라디오 이동 → 닫기, reduced-motion 계산 스타일 검증을 보강하면 좋다.
- **문서:** PRD v0.17의 기능·화면·변경 이력은 일치한다. DESIGN의 “그 위에” 배치는 M-01 해결이 필요하며, 펼친 칸 제목은 실제로 시각 숨김 legend라는 점을 명시하면 더 정확하다. task 문서의 잘못된 하위 완료 조건은 L-01에 기재했다.
