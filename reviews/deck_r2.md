[M-1] 8·validate — 방문 증가 가설의 비교 기준이 빠져 있음 — 근거: slides/validate.html:5,12는 열람률과 현장 방문 여부를 확인하지만 앱 미사용군·도입 전 등 기준을 제시하지 않습니다. app/src/domain/events.ts:128의 비율도 한 집단 내 열람 비율입니다. — 제안: “앱 사용군과 미사용군의 현장 확인 추가 방문율 비교”처럼 비교 설계를 한 줄 넣거나, 이번 단계의 가설을 “추가 방문 여부를 확인한다”로 좁힙니다. R1 H-2의 잔여이며 실제 이동 자동 측정 과장은 해소되어 Medium으로 평가합니다.

[M-2] 7·compare — 일반 앱 전체에 대한 기능 부재 단정이 남음 — 근거: slides/compare.html:5,7,8,9,11에서 제품·버전·확인일 없이 “일반적인 … 기본 기능”과 “없음”을 사용합니다. 범위 각주만으로 각 셀의 판정 근거를 추적할 수 없습니다. — 제안: 비교 대상을 특정하고 확인 근거를 적거나, 표를 디투어가 시연하는 세 가지 통합 경험 중심으로 바꿉니다. 실제 경쟁 제품의 기능 유무를 이번 검토가 새로 단정하는 것은 아닙니다.

[M-3] 2·problem — 출처 대기 중인 방문자 수가 확정 통계로 제시됨 — 근거: slides/problem.html:6,8,9,10,27,29에 93.1만→104.0만→119.1만과 +28%를 제시하지만 해당 출처가 없고, 참가신청서_개편안/src_v14/02.html:46에도 “[출처 기입]”입니다. — 제안: 사용자 확인 전에는 해당 차트와 대본의 수치 단정을 보류하거나 화면에 “출처 확인 중·잠정”을 표시합니다. **현재 상태 그대로 심사 발표에 사용하는 것은 부적절합니다.** 내부 작업본으로 대기시키는 것은 가능하지만, 의도적 대기 자체가 근거를 대신하지는 않습니다. 3장 사례와 8장 가설의 원문 연결도 발표자 참고자료에 정리하면 좋습니다.
