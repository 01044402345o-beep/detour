# T1.1 원도심 콘텐츠 데이터 검토 r1

검토일: 2026-11-23. 대상: `app/src/data/downtown.json`, `validate.ts`, `index.ts`, 두 테스트 파일 및 공유 타입. 기준: task.md T1.1, PRD v0.3 4장·F-01·F-04·8.1. 데이터·코드는 수정하지 않았습니다.

## M-1 — 장소 수준 알레르기 정보에 미확인 상태가 전달되지 않음

- 위치: `app/src/data/downtown.json:61`, `:641` (`ssd.allergens`, `gwc.allergens`), `app/src/data/validate.ts`의 `checkPlace`.
- 문제: 모든 메뉴가 `allergenStatus: unknown`인데 장소에는 밀·달걀·우유 / 대두·밀이 확정 목록처럼 들어 있습니다. 장소 타입에는 별도 확인 상태가 없고 해당 L10n에도 미확인 안내가 없어, 장소 상세가 `Place.allergens`를 표시하면 메뉴 상태와 상충합니다. 실제로 목업은 장소의 알레르기 목록을 그대로 표시합니다. 아직 구현되지 않은 화면의 오류를 단정하는 것이 아니라, 데이터가 제공하는 상충된 신호를 지적합니다.
- 근거: PRD F-04는 알레르기 미확인을 '확인 필요'로 표시하도록 요구합니다. 루트 한국어 note는 외국어 장소 상세에서 사용할 수 있는 표시 계약이 아닙니다. `checkPlace`는 L10n 존재만 검사하므로 이 상태가 통과합니다.
- 권장 수정안: 현장 확인 전 장소의 `allergens`를 생략하고 화면에서 메뉴 unknown 상태에 따라 확인 필요를 표시하거나, 해당 장소 L10n 자체를 '알레르기 정보 확인 필요 / 직원에게 확인' 취지의 세 언어로 명확히 작성하십시오. 기존 Place 타입에서 처리 가능한 수정이며, 미확인 장소가 단정적인 목록을 내보내지 않는 회귀 검사를 추가하십시오.

## L-1 — 발음 안내의 음절 누락

- 위치: `app/src/data/downtown.json:116` (`mr.roman`), `:840` (`gwc-4.kana`).
- 문제: 명란바게트의 `myeongnan bagete`는 마지막 '트'에 필요한 `eu`가 빠져 있습니다. 계산할게요의 `ケサナルケヨ`는 '할'의 ㅎ을 생략해 계산알게요처럼 유도합니다.
- 근거: PRD F-01의 개정 로마자 기반 발음 안내·가타카나 근사 표기 정책. [국립국어원 표기 설명](https://www.korean.go.kr/nkview/nknews/200010/27_7.htm)은 표준 발음 기반과 된소리되기를 로마자에 반영하지 않는 원칙을 설명합니다. 따라서 `maepge`, `gyesanhalgeyo`, `kalguksu`처럼 된소리를 겹자음으로 쓰지 않은 나머지 로마자 값은 결함으로 보지 않았습니다.
- 권장 수정안: `myeongnan bageteu`, `ケサンハルケヨ`(또는 발음상 된소리까지 안내하는 `ケサンハルッケヨ`)로 수정하십시오. 가타카나의 세부 근사 방식 자체를 일률적으로 오류 취급하지는 않습니다.

## L-2 — 으능정이 영문 이름이 다른 한국어 음절을 가리킴

- 위치: `app/src/data/downtown.json:287` (`eun.name.en`), `:464` (`mus.transitHint.en`).
- 문제: `Eunhaengjeong-i`는 으능정이가 아닌 '은행정이'에 대응합니다. 외국어 장소명 및 다음 장소 이동 안내가 같은 잘못된 이름을 사용합니다.
- 근거: PRD 4장 실제 장소 이름은 으능정이 문화의거리이며, [한국관광공사 영문 소개](https://english.visitkorea.or.kr/svc/whereToGo/locIntrdn/rgnContentsView.do?vcontsId=82410)도 `Euneungjeongi Culture Street`를 사용합니다. 목업에서 물려받은 값이어도 실제 장소 이름을 안내하는 목적에 맞게 정정할 수 있습니다.
- 권장 수정안: 두 위치를 `Euneungjeongi Culture Street`로 통일하십시오. 은행동을 뜻하는 `Eunhaeng-dong`은 그대로 유지하십시오.

## 확인 결과 및 검토 한계

- `cd app; npx vitest run src/data`: 테스트 파일 2개, 테스트 28개 모두 통과.
- 코스 1개·장소 4곳·메뉴 8개·문장 14개, 장소 순서, 주문/포장 가능 여부, 도보 시간, 대표/매운 메뉴 표시, 한국어 문장은 PRD와 일치합니다. 단어 칩을 공백으로 연결하면 원문과 일치하고, `몇 시에`, `해 주세요`처럼 의미 단위로 묶은 칩도 허용 가능한 분할입니다. 문장·칩의 EN/JA/ZH 뜻에서 학습 의미를 뒤집는 명백한 오역은 발견하지 않았습니다.
- 공기밥의 `공기`는 PRD 4.1·F-06이 명시하므로 목업의 `개`보다 우선하는 올바른 선택입니다. `area` 한국어와 `areaLocal` L10n 분리는 현재 공유 타입과 일치합니다. `hours`의 HH:MM–HH:MM과 `closedOn: mon`은 문자열 타입을 구체화한 합리적인 저장 규칙입니다. 24:00은 마감에만 허용합니다. 향후 영업상태 파서가 이 규칙을 함께 사용해야 합니다.
- 8개 메뉴의 `verified:false`, `allergenStatus:unknown`, 보문산메아리·오징어두루치기의 `priceKrw` 생략은 일관됩니다. 나머지 가격은 PRD가 허용한 현장 확인 전 예시가격이므로 verified:false라는 이유만으로 모두 삭제해야 한다고 판정하지 않았습니다. 광천식당 주소 및 사리 명칭·단독 주문 가능 여부 note의 확인 필요 표기도 있습니다.
- `checkedAt: 2026-11-10`은 형식상 유효하지만 실제 확인 활동의 근거까지 이번 코드 검토로 확인할 수는 없습니다. 현장 확인 전 예시 데이터라는 루트 note가 있으므로 이번 결함 수에는 포함하지 않았으며, 실제 확인일로 표시해 배포하기 전 근거와 날짜는 확인 필요입니다.
- 좌표는 네 곳 모두 원도심 근방(위도 36.3273~36.3305, 경도 127.4206~127.4273)으로 모여 있고 각 장소에 근사값·확인 필요 note가 있습니다. 검색에서 장소별 공식 좌표까지 확보하지 못했으므로 실제 건물/입구와 일치하거나 큰 오차가 없다고 인증하지 않습니다. 좌표·도보 시간·총거리의 현장/지도 대조는 확인 필요이며, 근거 없이 별도 위치 오류로 계상하지 않았습니다.
- 검증기는 필수 필드, 타입·열거값, 중첩 L10n, 유효 날짜·시간·휴무 형식, 좌표의 전 지구/대전 범위, 주문 가능과 메뉴 관계, 중복 ID·연속 순서·코스 참조, 칩 원문 재결합을 검사합니다. 고정 개수와 실제 한국어 콘텐츠는 데이터 테스트에서 검사하므로 런타임 검증기에 개수 상수가 없는 것은 별도 결함으로 보지 않았습니다. 번역·발음·실제 위치·확인일의 진실성은 구조 검증으로 보장되지 않으며 사람 검수가 필요합니다. `index.ts`의 로드 시 검증·순서 정렬·ID 조회에서 별도 문제는 발견하지 않았습니다.
