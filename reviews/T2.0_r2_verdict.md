## R2-L01 — 타당, L 유지

**근거 (`overlay.ts:48–54` 대조)**
- `FOCUSABLE`의 마지막 분기 `[tabindex]:not([tabindex="-1"])` 때문에 생기는 문제:
  - `<button disabled tabindex="0">`가 앞의 `button:not([disabled])` 분기에서는 빠지지만 이 분기로 다시 들어옵니다.
  - `tabindex="-2"` 같은 다른 음수 값도 걸러지지 않습니다.
- `focusableIn`은 `[hidden]` 조상만 제외하므로, CSS `display:none`이나 `visibility:hidden`인 요소가 후보에 남습니다.
- 그 결과 `trapTab`(`:67–78`)에서:
  - `last`가 숨김 요소이면 Shift+Tab 때 `preventDefault` 뒤 `last.focus()`가 실패해, 포커스가 제자리에 머뭅니다.
  - 실제 마지막 요소에서 Tab을 눌러도 `active === last`가 거짓이 되어 순환하지 않고, 브라우저 기본 이동에 맡겨집니다. 배경은 inert이므로 주소창 등 브라우저 UI로 빠집니다.
- R1 판정 지침 2("`disabled`가 아니고 보이는 것들 사이")를 충족하지 못한 것이 맞습니다. Codex가 실제 `overlay.ts`를 jsdom에서 돌려 네 경우를 모두 재현했다는 보고는 위 소스 분석과 일치합니다.
- 현실성: ReportSheet(T2.6)에는 "선택 전 비활성 보내기 버튼"이나 "선택 후에만 보이는 기타 입력" 같은 조건부 컨트롤이 들어갈 가능성이 있습니다. 시연 경로는 터치 전용이라 L을 유지하되, 고치는 비용이 작으므로 이번에 끝냅니다.

**수정 지침** (`overlay.ts`)
1. 선택자로만 거르지 말고, 후보를 모은 뒤 요소 상태로 거릅니다.
   ```ts
   const CANDIDATES = 'a[href], button, input, select, textarea, [tabindex]';
   function isTabbable(el: HTMLElement, root: HTMLElement): boolean {
     if (el.tabIndex < 0) return false;                       // -1, -2 … 모두 제외
     if (el.matches(':disabled')) return false;               // disabled 속성, disabled fieldset 포함
     if (el.closest('[hidden], [inert]')) return false;
     for (let n: HTMLElement | null = el; n && n !== root.parentElement; n = n.parentElement) {
       const s = getComputedStyle(n);
       if (s.display === 'none' || s.visibility === 'hidden') return false;
     }
     return true;
   }
   ```
   `getClientRects()`는 jsdom에서 항상 비어 있어 모든 요소를 숨김으로 판정하므로 쓰지 않습니다. 위 계산 스타일 검사는 jsdom에서 인라인 스타일과 `hidden`으로 검증할 수 있습니다. 실제 브라우저에서 클래스로 숨긴 요소도 같은 방식으로 걸러집니다.
2. 안전장치: `trapTab`에서 `focus()`를 호출한 뒤 `document.activeElement`가 대상이 아니면, 같은 방향의 다음 후보로 넘어가서 다시 시도합니다. 후보를 다 시도해도 안 되면 `root.focus()`로 시트 안에 붙잡습니다. 걸러지지 않는 예외 상황이 있어도 포커스가 시트 밖으로 나가지 않게 하기 위함입니다.
3. 테스트(`components.test.tsx` 또는 `overlay.test.ts`, jsdom):
   - `focusableIn` 결과에서 `style="display:none"`, `style="visibility:hidden"` 조상 아래의 버튼, `disabled tabindex="0"`, `tabindex="-2"`, `disabled` fieldset 안의 input이 빠짐.
   - 숨김 버튼을 맨 끝에 두면, 실제 마지막 요소에서 Tab → 첫 요소. 맨 앞에 두면, 첫 실제 요소에서 Shift+Tab → 마지막 실제 요소.
   - 실제 브라우저 가시성 검사(클래스로 숨김)는 Phase 2 E2E에서 ReportSheet로 1회 확인합니다. jsdom 단위 테스트와 구분해 usage에 적습니다.

## R2-L02 — 부분 타당, nit으로 조정

**코드 분석은 맞습니다**
- `Sheet.tsx:22, :44`의 `stack`은 effect가 실행된 순서이고, 그리는 순서는 포털에 붙은 순서와 CSS(같은 위치·같은 쌓임 규칙)를 따릅니다. 둘을 맞추는 처리가 없습니다.
- `lockBackground`(`overlay.ts:21–26`)는 `#app-overlay` 바깥 형제만 inert로 만듭니다. 그래서 겹쳤을 때 아래 시트는 탐색 가능하고, `aria-modal="true"`인 dialog가 두 개가 됩니다.

**그러나 데모에서 시트가 겹치는 실제 경로는 없습니다**
- 계획된 시트는 둘뿐입니다:
  - 제보 시트: `ui/ReportSheet`, T2.6 소유, T2.3 장소 상세의 "정보가 달라요"에서 엽니다 — `task.md:226, 239`.
  - 장소 전환 확인 시트: T2.3, "다른 장소에서 담으려 하면 기존 주문 비울지 확인" — `task.md:228`.
- 두 시트 모두 **배경 화면의 버튼**으로만 열립니다. 시트가 열린 동안 배경은 inert(R1 M01 수정)이라, 사용자 조작으로 두 번째 시트를 열 수 없습니다.
  - 제보 시트 안에는 메뉴 담기가 없으므로 그 안에서 전환 확인이 시작될 수 없습니다.
  - 전환 확인 시트 안에도 제보 버튼이 없습니다.
  - 목업(`mockup/index.html:767–769`)에서도 제보는 보내면 시트를 닫고 토스트를 띄울 뿐, 다른 시트로 이어지지 않습니다. 화면을 이동하면 시트를 닫습니다(`:744`).
- 겹침이 생기려면 화면 코드가 effect나 타이머로 시트를 하나 더 여는 경우뿐입니다. 이는 지금 계획에 없는 사용법입니다.
- 따라서 결함이 일어날 조건이 데모 범위에 없습니다. 반대로 겹침을 제대로 지원하려면 z-index 동기화, 아래 시트 inert, 포커스 복귀 경로 재설계가 필요해 비용이 큽니다. **겹침을 지원하지 않는 것으로 계약을 좁히는 것**이 맞습니다. Codex 권장안의 두 번째 선택지입니다.
