## R3-L01 — 이벤트 상한을 전체 영속 데이터의 상한으로 설명 (Low)

- **위치:** `app/src/sw/canPersist.ts:5`, `reviews/T3.1_offline.md:99`; 근거가 된 `reviews/T3.1_r2_verdict.md`의 “앱 데이터 규모 추정” 절.
- **문제:** 이벤트 500건 제한을 근거로 전체 앱 데이터가 최대 약 100KB라고 단정한다. 그러나 `reports`는 별도 영속 배열이며 개수 제한 없이 증가한다. “크기가 커질 수 있는 것은 events뿐”이라는 판정문 전제도 코드와 다르다.
- **근거:** `useAppStore.ts:309–318`은 유효한 제보마다 `reports: [...s.reports, report]`를 실행하고, `:334`는 전체 reports를 저장한다. `MAX_EVENTS`는 `appendEvent()`에만 적용된다. 허용 종류 `closed`, 장소 `ssd`, 13자리 시각으로 구성한 제보 3,000건의 JSON은 **156,001 UTF-8 바이트**였다(메모리 내 계산, 파일 생성 없음). 이는 시연에서 그만큼 제보한다는 예측이 아니라, 100KB가 구현상 최대치가 아님을 확인하는 반례다.
- **권장 수정안:** 해당 상한 표현을 다음처럼 바꾼다. **“이벤트는 500건으로 제한되지만 제보 목록에는 개수 상한이 없어 전체 저장량의 고정 상한은 보장하지 않습니다. 관리되는 시연 범위에서는 앱 스냅숏만 저장 실패하는 경우를 알려진 제한으로 수용합니다.”** 판정문의 용량 설명도 같은 의미로 정정한다. 이를 위해 코드 동작이나 store를 바꿀 필요는 없다.

## 검증과 결론

이번 변경은 주석·문서이므로 빌드와 테스트는 재실행하지 않았다. 함수 본문의 작은 probe 쓰기/삭제, 예외 시 false 반환이 유지됨을 읽어 확인했고, R2의 관련 테스트 29건 통과 결과를 유지한다.
