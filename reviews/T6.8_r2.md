# T6.8 코드 검토 R2

검토일: 2026-11-26. 지정된 git diff·신설 파일, R1 보고서와 판정, 연결된 언어 화면·저장소·PWA 코드를 검토했다. 소스 수정·커밋·푸시는 하지 않았으며 직접 작성한 파일은 이 보고서뿐이다. 허용된 검사 실행으로 빌드·테스트 산출물은 생성된다.

## 판정

**H 0 / M 0 / L 0 — R1 지적 2건 해결, 새 회귀 발견 없음.** 홈 문서 새 로드에서는 인트로를 표시하고, 언어 선택 완료 사용자의 딥링크는 유지하는 명시된 구현 범위에 대한 판정이다. 사용자 원문의 ‘항상’을 모든 주소 진입·앱 창 재개까지 확대해서 구현했다는 뜻은 아니다.

## R1 해결 확인

| 항목 | R2 확인 |
|---|---|
| L-01 문서 예외 조건·결정 주체 | 해결. `prd.md:150`은 coordinator 구현 범위, 언어 미선택 시 어느 주소든 인트로 → 홈, PWA 창 재개·BFCache 복원 제외를 명시한다. `DESIGN.md:87`도 언어 선택 여부에 따른 예외를 기록했고, `task.md:442`와 `launchIntro.ts:2`~주석에도 해석 주체와 경계가 반영됐다. task의 다음 줄에 있는 딥링크 보존 문장은 바로 앞의 미선택 예외와 함께 읽으면 정합적이다. |
| L-02 새 실행 계측·StrictMode 미검증 | 해결. `AppRoutes.test.tsx:106`은 pending=true, 저장 언어 en, StrictMode에서 실제 MemoryRouter 이동을 수행하고 이벤트 배열이 정확히 `['lang', 'home']`인지 검사한다. 전체 Vitest 실행에서 통과했다. `setup.ts:4`~주석은 false 기본값이 이미 진입 판단을 끝낸 페이지용 fixture라는 이유와 전용 검증 위치를 명시한다. |

StrictMode 테스트는 화면들을 빈 section으로 대체하므로 실제 시작 버튼을 클릭하는 통합 테스트는 아니다. 다만 실제 버튼과 동일한 `navigate('/', { replace: true })`를 호출하여 이번 지적의 핵심인 가드·라우터·계측의 이중 effect 계약을 검증한다. 실제 시작 버튼과 저장 언어 유지 흐름은 Lang 화면 테스트 및 S8 E2E가 별도로 통과하므로 이를 미해결 지적으로 재등록하지 않는다.

## 경계·회귀 검토

| 경우 | 확인 결과 및 검증 범위 |
|---|---|
| 홈 주소 vs 모든 주소 | 홈을 일반 실행 진입점으로 보고 딥링크를 보존하는 해석은 합리적이다. 원문의 유일한 해석은 아니지만 문서가 구현 범위임을 이제 구분한다. |
| PWA 아이콘 | manifest의 `start_url`은 `/edulleo/`; HashRouter의 홈 경로로 새 문서를 열면 pending=true가 인트로로 보낸다. 기존 PWA 창 재개는 새 모듈 로드가 아니므로 재표시하지 않는다. 실제 설치 PWA 아이콘 조작은 이번 실행 범위 밖이다. |
| QR·특정 화면·새로고침 | 저장 언어가 있으면 첫 특정 경로를 유지하고 첫 effect에서 pending을 해제하므로 이후 홈 이동도 정상이다. 언어가 없으면 기존 가드가 우선하여 인트로 → 홈이다. QR의 원래 목적지 복원은 기존에도 없었고 새 회귀가 아니다. |
| 오프라인 | SW가 앱 셸과 lazy 청크를 프리캐시하므로 새 문서의 가드 로직은 온라인과 동일하다. 전체 P3 E2E에서 설정·장소·문장·코스 오프라인 새로고침이 통과했다. 오프라인 홈 → 인트로 자체의 전용 E2E는 없으며 코드 검토에 근거한 판단이다. |
| 언어 미선택 첫 실행 | 기존 lang=null 가드 유지. Lang 화면의 기본 EN 저장 후 시작 → 홈 테스트와 기존 언어 선택 E2E 통과. |
| 시작 후 뒤로가기 | 가드와 시작 버튼 모두 replace이므로 이번 리다이렉트가 별도 인트로 이력 항목을 추가하지 않는다. 같은 문서의 이전 홈으로 돌아가도 pending=false다. 실제 브라우저 뒤로가기·BFCache 복원을 전용 자동 테스트로 재현한 것은 아니다. |
| StrictMode·계측 | render는 pending을 읽고 effect는 false를 대입하므로 이중 실행이 멱등이다. 가드에서 Navigate 반환 시 logger가 렌더되지 않아 숨겨진 홈 기록이 없으며, logger의 location.key 중복 억제와 추가 StrictMode 테스트가 인트로·홈 각각 1회를 확인한다. |
| 테스트 기본값·모듈 상태 | 전역 beforeEach의 false는 기존 화면 테스트가 새 실행을 재현하지 않도록 하지만 의도가 주석으로 드러난다. 새 실행 전용 테스트 4개는 true를 설정하며 S8은 실제 문서 재로드를 검사하므로 신규 계약 전체를 가리지 않는다. 테스트마다 리셋되어 누수도 방지한다. |
| HMR | launchIntro 모듈 자체가 개발 중 재평가되면 pending=true로 돌아갈 수 있다. 이는 배포 문서 수명과 다른 개발 도구 동작이며 새 운영 회귀로 판단하지 않는다. |
| 기존 E2E | openHome은 홈 또는 인트로를 기다린 뒤 필요하면 시작한다. S5의 언어 전환·한국어 고정 영역, S6의 제보 건수 계약이 유지됐고 전체 E2E가 통과했다. S8이 인트로 필수 표시를 독립적으로 단언한다. |

문서의 기존 F-01 ‘첫 실행 시 언어 선택’은 첫 선택 필요성을 설명하며 ‘첫 실행에만’이라는 제한이 아니므로 갱신된 S00과 충돌하지 않는다. task의 T6.1 완료 내역은 과거 작업 기록으로 보았다.
