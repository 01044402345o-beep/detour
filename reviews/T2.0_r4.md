# T2.0 토스트 폭 수정 확인 R4 — Codex

2026-11-23. 대상: T2.1 R1 판정의 T2.1-L-01(T2.0 소유), `app/src/styles/ui.css`의 `.ui-toast`, 측정 기록 `reviews/T2.0_fix_r3.md`. 이 보고서만 작성했으며 구현 파일은 수정하지 않았다.

## 해소 판정

**T2.1-L-01 해소.** `ui.css:302`에 `width: max-content`가 추가됐고 기존 `max-width: calc(100% - 32px)`가 유지된다. width:auto의 절대 배치 요소가 left:50% 때문에 프레임 절반 정도의 가용 폭으로 축소되던 원인을 직접 제거했다. nowrap은 추가하지 않았으며 판정서의 권장 수정과 일치한다.

## 다른 화면에서의 부작용 검토

- **긴 문구:** 전역 `box-sizing: border-box`가 적용되므로 max-width에는 좌우 padding도 포함된다. 토스트 박스는 프레임 너비에서 32px을 뺀 상한을 지키고, 일반 공백이 있는 영어 문장과 일본어·중국어 문장은 그 안에서 줄바꿈할 수 있다. height 고정도 없어 여러 줄이 잘리는 새 원인은 없다.
- **가운데 정렬:** left:50%는 포함 블록인 `.app-frame`의 중앙이고 translateX(-50%)는 실제 토스트 폭의 절반을 되돌린다. 폭이 내용에 따라 달라져도 중앙은 유지된다. 애니메이션의 가로 이동값도 -50%를 유지하며, reduced-motion에서 애니메이션을 끄더라도 기본 transform이 적용된다.
- **다른 화면:** Home·Settings 외 Place/Order의 수량 안내, Place의 길찾기 안내, Phrases/Saved의 저장·삭제 안내, ReportSheet의 감사 안내 호출과 EN·JA·ZH 사전을 확인했다. 모두 일반 번역 문구이고, 화면별 `.ui-toast` 덮어쓰기는 발견하지 못했다. 공용 ToastProvider의 상태·타이머·live region 동작은 이 CSS 변경으로 바뀌지 않는다.
- **데스크톱:** 일반 화면은 430px 프레임을 기준으로 제한·정렬된다. `/report`의 넓은 프레임에서도 동일한 계산이 적용되므로 짧은 문구가 화면 전체 너비로 늘어나지 않고 내용 폭으로 중앙에 놓인다.
- **보장 범위:** 공백 없는 매우 긴 URL·식별자처럼 줄바꿈할 수 없는 문자열은 max-width만으로 텍스트 넘침까지 막을 수 없다. 현재 토스트 호출·사전에는 해당 입력이 없고 수정 전부터 존재한 일반적인 제한이므로 신규 결함으로 집계하지 않는다. 향후 그런 문자열을 넣을 때는 overflow-wrap 정책을 별도로 정해야 한다.

## 측정 기록 대조와 검증 한계

작성자의 `T2.0_fix_r3.md`는 360·390·430px 및 1280px 데스크톱의 430px 프레임에서 EN·JA·ZH 문구를 측정했다. EN soonToast는 360/390px에서 각각 328/358px 폭·2줄·좌우 16px, 430px에서 371px 폭·1줄이며 JA soonToast는 모든 폭에서 1줄로 기록됐다. 이는 수정된 폭 상한과 중앙 정렬 계산에 부합한다.

이번 검토는 실제 CSS, 전역 box-sizing, 애니메이션, Toast 구조, 호출 문구와 작성자 측정 기록을 대조한 소스 검토다. 작성자의 Edge headless 측정이나 저장소 밖 캡처를 독립 재실행·열람했다고 주장하지 않는다. 측정 글꼴이 Pretendard 미로딩 상태라는 제한도 유지되며, 실제 앱 글꼴에 따른 줄 수는 화면 시각 대조에서 달라질 수 있다. CSS 한 속성 수정에 대해 레이아웃을 검증하지 못하는 jsdom 테스트를 추가하거나 전체 테스트를 반복 실행하지 않았다.
