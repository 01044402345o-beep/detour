## 4. 공용 UI

- Button: `ink`·`acc` = 파란 채움(누르면/호버 시 blue-deep), `sea` = 연파랑 바탕 + 파란 글자, `ghost` = 흰 바탕 + `--line` 테두리. 반경 12px, 16px/700. variant 이름은 그대로.
- Pill: acc = tint/blue, sea·plum = tint/blue-deep, ink = ink/흰색, line = 흰 바탕 + 테두리. 톤 이름은 그대로.
- 누름 `scale(.97)` + `cubic-bezier(.23,1,.32,1)` 160/200/240ms(버튼·카드 버튼·아이콘 버튼·듣기). 탭 하이라이트 없앰과 `touch-action: manipulation`(global + 각 요소). 호버는 `(hover:hover) and (pointer:fine)` 안에서만. 움직임 줄이기 설정이면 global.css에서 animation·transition을 모두 끔. 초점 표시는 3px 파랑 외곽선.
- 굵기 800 제거(TopBar·Sheet 제목 → 700). 공용 CSS 4개에 800·900이 없는지 테스트로 검사.
- TabBar: 12px/500, 활성 탭은 파랑/700. Sheet: 흰 바탕, 반경 20, scrim 막. Toast: ink 바탕, 반경 12. ListenButton: 연파랑(round·pill), 재생 중 파랑. TTS 안내 글자는 `--danger`(소리를 낼 수 없는 실패 상태).
- `ui/Logo.tsx`: `Logo`(size·tile `blue|white|deep`·wordmark·label) + `LogoMark`. SVG는 DESIGN.md 4장 그대로, 타일 반경은 한 변의 27%. `ui/index.ts`에서 내보냄.
- `.num` 유틸 클래스(IBM Plex Mono, tabular-nums).
- `sw/updateToast.css`: 새 토큰 적용, 주 버튼은 파랑. 초점 외곽선은 ink 토스트 위에서 파랑 대비가 2.9:1로 낮아 `--signal`(9.50:1)을 씀(DESIGN.md 9장 '3px 파랑'과 다른 예외).

## R1 수정 (Codex `T6.0_r1.md` H0 M2 L1 → 판정 `T6.0_r1_verdict.md`)

### R1-M-01·M-02 잠금 다시 작성 — `app/scripts/lockDir.mjs`(새 파일, `.d.mts` 타입) + `i18n-patch.mjs`가 사용

- **소유 토큰:** `mkdir(.patch.lock)`에 성공하면 곧바로 `owner`에 `{token, pid, time}`을 씀. 해제는 owner 토큰이 자기 것일 때만 함(이전 소유자가 늦게 해제해도 남의 잠금을 지우지 않음). 해제 실패는 경고만 출력.
- **회수 조건:** owner의 PID가 살아 있으면(`process.kill(pid,0)`, EPERM도 살아 있음으로 봄) 아무리 오래돼도 회수하지 않음. PID가 죽었으면 회수. owner를 아직 못 쓴(쓰기 전 비정상 종료) 잠금은 60초가 지나면 회수.
- **원자적 회수:** 별도 회수 잠금(`.patch.lock.reclaim`, mkdir) 안에서 잠금 정체(토큰, owner가 없으면 mtime)를 다시 읽어 처음 본 것과 같을 때만 고유 이름으로 `rename`한 뒤 지움. 늦게 온 두 번째 회수자는 새로 잡힌 잠금을 건드리지 않음.
- **오류 처리:** 경쟁으로 사라진 경로(ENOENT)는 바로 다시 시도. 그 밖의 오류(EPERM·EACCES·EBUSY 등)는 원인을 기억하고 100ms 쉬었다 다시 시도. 모든 반복 경로에서 deadline을 검사하고, 넘으면 종료 코드 4와 원인(마지막 오류 코드, 또는 잡고 있는 pid)을 출력.
- **CLI 추가:** `--lock-timeout <ms>`(기본 30초). 테스트 전용 환경 변수 `I18N_PATCH_TEST_HOLD_MS`(사전을 읽은 뒤 잠금을 쥔 채 기다림).
- **테스트 `src/i18n/lockDir.test.ts` (13개, 실제 임시 폴더 + 오류를 끼워 넣는 fs 래퍼 + 가짜 시계):**
  - 토큰 해제(남의 토큰은 해제 안 함)
  - 살아 있는 소유자는 오래돼도 회수하지 않고 시간 초과
  - 죽은 소유자는 회수, owner 없는 잠금은 새것이면 대기·60초 지나면 회수
  - 두 회수자 경쟁에서 새 잠금 보존
  - 이전 소유자의 늦은 해제
  - mkdir EPERM·EACCES·EBUSY가 계속되면 시간 초과(원인 보존, 매 반복마다 대기)

### R2-M-01 자동 회수 제거 — `app/scripts/lockDir.mjs`

- 회수 잠금(`.patch.lock.reclaim`)과 rename으로 회수하는 경로(`tryReclaim`)를 모두 없앰. 잠금이 있으면 소유 PID가 살아 있든 죽었든 100ms 간격으로 기다리다가, deadline을 넘으면 `ELOCKTIMEOUT` → CLI 종료 코드 4로 끝남. 안내에는 소유 PID·시각(owner가 없으면 "unknown owner"와 폴더 시각)과 "If no other patch is running, remove it with --break-lock (refused while the owner pid is alive)."를 넣음.
- 해제는 그대로 자기 토큰일 때만. 대기 중인 프로세스는 남의 잠금을 지우거나 옮기지 않음(테스트에서 rename·rm 호출 0회 확인).
- ENOENT가 아닌 오류(EPERM·EACCES·EBUSY 등)를 deadline 안에서 쉬며 재시도하고 원인을 보존하는 동작은 유지.
- **수동 명령 `node app/scripts/i18n-patch.mjs --break-lock [--dir …]`**(coordinator 전용):

  | 잠금 상태 | 처리 | 종료 코드 |
  |---|---|---|
  | 잠금 없음 | "no lock" | 0 |
  | 소유 PID가 죽음 | 지움 | 0 |
  | 소유 PID가 살아 있음 | 거부 | 5 |
  | owner 없음, 60초 안 됨(만드는 중일 수 있음) | 거부 | 5 |
  | owner 없음, 60초 지남 | 지움 | 0 |
  | 패치 파일과 같이 줌 | 사용법 오류 | 2 |

- 테스트 교체:
  - `lockDir.test.ts` 17개: 토큰 해제, 풀리면 이어서 획득, 살아 있는/죽은/owner 없는 잠금 모두 지우지 않고 대기 후 시간 초과(안내 문구·대기 횟수·rename/rm 0회), 이전 소유자의 늦은 해제, breakLock 4가지 경우, mkdir EPERM·EACCES·EBUSY와 stat EPERM 시간 초과(원인 보존), 일시적인 오류, ENOENT 즉시 재시도, timeout 0
  - `i18nPatch.test.ts`: 살아 있는 PID → 4 + `--break-lock` 거부(5) + 파일 그대로 / 죽은 PID → 4, `--break-lock`으로 지운 뒤 적용 성공 / 잠금 없음 0·패치와 같이 주면 2 / **두 프로세스 동시 적용 테스트는 유지**
- `task.md` Phase 6 번역 파일 규칙 끝에 한 문장 추가: "잠금이 남아 종료 코드 4가 나면 coordinator에게 알리고, coordinator가 다른 작업이 없을 때 `node app/scripts/i18n-patch.mjs --break-lock`으로 정리합니다(소유 PID가 살아 있으면 거부)."
