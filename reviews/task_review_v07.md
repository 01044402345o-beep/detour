## M-01 — 4A의 시연 가능 정의와 PRD의 시연 전 확인 의무 관계가 미정리

- **위치:** `task.md:78, 300`의 4A 완료 정의, `:322`의 T4.4 후순위 반영; `prd.md:75–76`, 10장.
- **문제:** 4A는 T4.3·T4.5만 끝나면 “시연 가능한 데모”라고 정의하지만, 기준 PRD 4장은 메뉴·영업시간·주문 방식 및 상호 사용 범위를 **시연 전에** 확인하도록 요구한다. PRD F-03·F-04의 “현장 확인 전 · 예시 정보” 배지는 확인 전 화면 표시 방법을 정한 것이며 시연 전 확인 의무를 명시적으로 면제하지 않는다. task.md의 “PRD 우선” 규칙도 유지돼 두 문서를 함께 적용하면 완료 기준이 충돌한다.
- **근거:** PRD 1.3의 180초·음성/텍스트 경로는 4A의 기능 점검으로 확인할 수 있지만, 그것만으로 PRD 4장·10장의 콘텐츠 조건까지 충족했다고 볼 수 없다. 사용자 결정에 따라 일정을 나누는 것은 가능하며, 문제는 그 결정이 기존 필수 조건에 어떤 예외를 주는지 기록되지 않은 점이다.
- **권장 수정안:** 4A가 내부/기술 리허설 완료인지, 확인 전 표시를 전제로 심사 시연까지 허용하는 사용자 승인 예외인지 명시한다. 후자라면 승인된 범위에서 PRD 4장·10장과 task.md 완료 정의를 함께 맞추고, 현장 정보 검증 완료나 실제 이용 안내의 보증을 뜻하지 않는다고 구분한다. T4.1을 다시 4A 선행 조건으로 강제할 필요는 없다.

## M-02 — 4A 중 앱 화면 변경에 대한 영상 정합성 조건이 빠짐

- **위치:** `task.md:76–77`(4A-c·d), `:263`(영상 갱신을 4B로 한정), `:315–317`(T4.5), `:337–341`(T4.7·T4.5b).

- **근거:** T2.7 최초 녹화 대상은 Phase 2 배포 커밋이다. v0.7은 영상 갱신을 “Phase 4B에서 T4.1a로 바뀐 화면”으로 제한하지만 4A-d도 i18n·콘텐츠·수사 표기까지 수정하고 배포할 수 있다. 4A에서도 시연 영상이 쓰인다면 현재 조건으로는 오래된 문구나 화면이 남는다.

## M-03 — 4B의 확인 배지 전환과 재실행 대상 E2E의 고정 기대값이 충돌

- **위치:** `task.md:82–83`(4B-b·c), `:333`; `app/e2e/p3-offline.spec.ts:70`, `app/e2e/s6-report-count.spec.ts:16–18`.
- **문제:** T4.1a에서 확인한 장소를 `verified:true`로 전환한 뒤 Phase 2·3 E2E를 재실행하도록 정했으나, 현재 E2E는 네 장소 모두 확인 전 배지여야 하고 성심당 제보 시트도 확인 전 문구여야 한다고 단정한다. 정상적인 확인 상태 전환만으로도 4B-c가 실패한다. 후보 커밋 고정 전에 테스트 기대값을 새 데이터에 맞추는 작업이 배포 절차에 없다.
- **근거:** `p3-offline`은 네 장소를 순회하며 `place.unverified`를 무조건 기대한다. `s6-report-count`도 성심당의 확인 전 문구를 무조건 기대한다. 테스트를 통과시키려고 정상 verified 전환을 되돌려서는 안 된다.
- **권장 수정안:** 4B-b와 후보 커밋 고정 사이에 coordinator의 E2E 기대값 검토·갱신을 명시한다(소유는 기존 0.2절대로 coordinator). 실제 후보 데이터의 verified/checkedAt에 맞는 배지와 오프라인 기능을 검증하고, 미확인 장소가 남으면 그 장소의 경고 유지도 확인한다. 4A 번역 반영이나 4B 콘텐츠 변경으로 달라지는 고정 문구·메뉴 기대값도 같은 단계에서 점검한다. 이번 검토에서 테스트 파일은 수정하거나 실행하지 않았다.
