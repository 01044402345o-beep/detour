## M-01 — S13 뒤로 버튼의 접근 가능한 이름이 사용자 언어에 따라 바뀜

- **위치:** `app/src/screens/Report/index.tsx:73`, `app/src/screens/Report/Report.test.tsx`의 마지막 테스트.
- **문제:** 한국어 고정 리포트 안의 뒤로 버튼만 `t('common.back')`을 사용한다. EN에서는 `Back`, JA/ZH에서는 해당 사전 문구로 바뀌며, 상위 `lang="ko"`를 상속하므로 스크린 리더에도 한국어가 아닌 버튼 이름이 한국어 언어 문맥으로 전달된다. 현재 테스트는 오히려 EN 이름 `Back`을 기대하여 이 예외를 고정한다.
- **근거:** PRD 1.3은 운영자 리포트를 한국어 고정으로 정하고 task.md T2.6은 그 문구를 `operatorKo.ts`에 두도록 한다. 접근 가능한 버튼 이름 역시 사용자 문구이며, 작성자 보고의 “OPERATOR_KO만” 설명과도 다르다. 언어 선택용 자국어 이름을 재사용한 범례는 목업의 기존 표현이지만, 이 버튼은 언어 설정에 따라 실제로 변경된다.
- **권장 수정안:** coordinator를 통해 공용 `operatorKo.ts`에 한국어 뒤로 이름을 추가한 후 S13 버튼에서 사용한다. 세 언어 모두 같은 한국어 접근 가능 이름인지 검사하도록 테스트를 변경한다.

## L-01 — 모바일 CSS가 1박 전환 막대의 두 열 구성을 덮어씀

- **위치:** `app/src/screens/Report/Report.css:115`, `app/src/screens/Report/Report.css:240`, `app/src/screens/Report/index.tsx:161`.
- **문제:** `.rep-hbar--solo`는 막대·수치 두 자식에 맞춰 `1fr 44px`를 지정하지만, 760px 이하의 뒤쪽 `.rep-hbar`가 같은 명시도로 이를 `minmax(0, 120px) 1fr 40px` 세 열로 덮어쓴다. 따라서 휴대폰에서는 1박 전환 막대가 첫 120px 열에 갇히고 `7%`는 두 번째 열에 놓이며 마지막 수치 열은 빈다. 다른 지표의 수치 끝선과 어긋나고 막대가 불필요하게 짧아진다.
- **근거:** 두 클래스는 같은 요소에 붙어 있다. CSS 소스 순서와 동일한 명시도 때문에 모바일 규칙이 이긴다. 목업의 해당 막대는 명시적으로 두 열(`1fr 44px`)을 사용한다. 제공 모바일 캡처에는 이 중간 카드가 나오지 않아 시각 비교에서 놓칠 수 있다.
- **권장 수정안:** 모바일 규칙 뒤에 `.rep-hbar--solo { grid-template-columns: 1fr 40px; }`를 추가하거나 세 열 규칙을 일반 막대에만 적용한다. 360·390·430px에서 해당 카드의 막대 폭과 수치 정렬을 확인한다.

## 확인된 정상 동작 및 목업 차이 판정

- 예시 KPI는 `SAMPLE_KPI`만 사용하고 내 기기 영역은 별도 section이다. 제보 추가가 예시 12건에 합산되지 않으며 내 기기 건수는 `reports.length`다. 이벤트를 비운 뒤에도 제보 2건이 유지되는 테스트가 있다.
- 내 기기 추가 방문 비율·다음 방문지에는 모두 실제 기준 ID `ssd`를 넘긴다. 추가 방문 비율·다음 방문지·많이 쓴 문장·이용 기록 수 각각에 `MAX_EVENTS` 기반 “최근 500건 기준”이 있다. 문장·장소 이름은 데이터에서 조회한다.
- S13 주 콘텐츠는 `OPERATOR_KO`와 데이터 한국어 이름을 사용한다. 일반 UI의 하드코딩 문구는 발견하지 않았다. 예시 수치·기간·색상 상수는 명시된 예시 리포트 데이터로 타당하다. 언어 범례의 자국어 이름은 목업과 공용 예외 목록에 있는 표현이다.
- `/report`의 wide 라우트와 1060px 패널, 모바일 KPI·카드 1열은 소스와 제공 캡처에서 확인된다. 위 L-01은 카드 내부의 별도 레이아웃 문제다.
- ReportSheet는 계약대로 네 종류, 유효 장소 부제, 확인 전 표시, 잘못된 장소 ID의 일반 제보 처리, onSent·onClose·토스트를 구현한다. `addReport`만 호출하고 별도 `report_sent`를 기록하지 않는다. store에서 제보·이벤트를 함께 저장하며 단일 제보당 이벤트 1건 테스트가 통과한다. 모달 이름·포커스 관리·배경 inert는 공용 Sheet에 위임한다.
- 문장 모음의 듣기·연습 state 전달·북마크 토글, 저장 목록·해제·듣기·제보가 테스트된다. 북마크는 persist 대상인 `saved.phrases`를 사용하고 localStorage 쓰기를 검사한다. 실제 새로고침 재수화까지 이 컴포넌트 테스트가 실행하는 것은 아니므로 브라우저 E2E에서 최종 확인하면 된다.
- 예시·내 기기 제보 합산 및 “내 기기 N건 반영” 제거는 F-16a 우선 적용으로 타당하다. 북마크·저장 문장 섹션 추가는 F-13 충족에 필요하다. 대비 보정을 위한 강조색 변경과 공용 44px 버튼 사용도 타당하다.
- 저장 화면의 번호 배지 대체는 작성자가 공개한 시각적 단순화이며 이름·순서·상세 이동은 유지한다. 장소를 특정하지 않은 저장 화면 제보는 일반 제보 계약과 일치하고, 마지막 방문 장소로 암묵적으로 귀속시키지 않는 선택도 타당하다. 실제 장소 제보는 장소 상세에서 placeId를 전달한다.
- 리포트 뒤로 버튼 추가 자체는 독립 라우트에서 필요한 이동 경로로 타당하나 한국어 고정은 M-01대로 보완해야 한다. 내 기기 Top5에서 예시의 “듣기+연습+직원” 부제를 빼고 실제 `topPhrases` 집계를 사용하는 차이도 타당하다.
