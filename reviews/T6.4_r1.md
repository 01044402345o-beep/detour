## M-01 — 가격 미정 문구 변경으로 기존 S4 E2E가 세 언어 모두 실패

- 위치: `app/src/screens/Place/MenuTab.tsx:81`, 영향: `app/e2e/s4-gwc-total-tbd.spec.ts:10`.
- 메뉴 화면은 이제 `menu.priceAsk`를 출력하지만 S4는 여전히 `menu.priceTbd`를 기대한다. 실제 적용 번역은 EN `Price to be confirmed` → `Price: ask staff`, JA `価格要確認` → `価格: 店員に確認`, ZH `价格待确认` → `价格：请询问店员`로 서로 다르다. 따라서 광천식당의 `menu-od` 검사에서 주문 담기 이전에 실패한다.
- Place 단위 테스트는 새 문구로 갱신했지만 E2E 계약 변경은 작업 보고의 인계 목록에서 빠졌다. 디자인에 맞는 문구 변경 자체는 타당하며, 가격 미정 합계 처리도 유지된다.
- 조치: E2E 소유자인 coordinator가 **장소 화면의 10행만** 새 키로 갱신하고 세 언어 S4를 재검증한다. 같은 테스트의 Order 화면 `line-od` 검사는 실제 Order 출력에 맞춰 별도로 유지한다. T6.4 worker가 소유 범위 밖 E2E를 직접 수정할 필요는 없다.
- 근거 수준: 소스 및 적용된 세 언어 문자열 대조로 확정. 이번 읽기 전용 검토에서는 Playwright를 실행하지 않았다.

- 위치: `app/src/screens/Place/index.tsx:156,275`, `app/src/screens/Place/place.css:161,626–640`.

## 기준·회귀·테스트 검토

- 사진 머리/사진 없는 파란 머리, 한글 및 사용자 언어 제목, 출처, 진행 표시, 탭, 선택 줄 연파랑, 중립색 닫힘·가격 미정·알레르기, 담은 항목이 있을 때만 주문 바라는 구성은 기준에 부합한다.
- h1의 두 언어 병기, 다음 정류장 사용자 언어 표기, 제보 버튼 유지, 수량 0의 기존 AddButton 유지는 기능·접근성·소유 범위 관점에서 수용 가능하다. PlaceArt는 장소 화면에서 import하지 않으며 다른 화면 의존성이 남아 있는 상태에서 파일을 보존한 판단도 타당하다.
- 현장 확인 전 안내/확인일 분기, 비제휴·정정 안내, 메뉴 예시 가격·가격 미정·알레르기 안내를 유지한다. 상태 참고 안내도 모든 탭에서 유지한다.
- 장소 저장·제보, 메뉴 수량·최대 수량·장소 변경 확인, 주문 바 이동, 문장 탭 → 연습의 navigation state, place_view·phrase_play 로직에 의도하지 않은 변경은 발견하지 않았다. 기존 screen/menu/orderbar/verified/phrase testid 계약은 유지된다.
- 사진은 photos.ts 조회·언어별 의미 있는 alt·eager 로딩·11.5px 출처를 사용한다. 글자 영역의 막은 위쪽 28px 전환 구간 아래 40px 패딩에서 시작하므로 코드상 글자 뒤 0.86 이상이다. 색상은 새 토큰을 사용하며 버튼 44px·초점 3px·전역 및 화면 reduced-motion 처리가 있다. 실제 최악 배경 대비 4.5:1 계측과 세 언어 전체 키보드 검증은 T6.7에서 필요하다.
- 테스트 diff에서 기존 기능 검사를 삭제한 흔적은 없다. 떠 있는 연습 버튼 제거에 따른 기대만 바꾸고 문장 탭 진입 검사를 유지·보강했다. 새 사진/글자 머리·진행·다음 영업·번역·선택 상태 검사도 추가했다. 다만 CSS 클래스 검사는 실제 대비·레이아웃 검증을 대신하지 않는다.
- nextOpening의 오늘/내일/휴무 건너뛰기 구현을 확인했다. 기존 영업 상태 함수는 변경하지 않았으며 자정 넘김 판단과 같은 휴무 정책을 사용한다.
- T6.4 패치의 EN/JA/ZH 각 10개 키가 적용 파일과 모두 일치한다. 이름공간은 place/menu뿐이며 누락·원시 키 노출은 발견하지 않았다.
- 보고된 수정 파일은 소유 범위 안이다. 공유 작업 트리의 범위 밖 변경은 다른 병렬 작업과 구분할 수 없으므로 T6.4의 수정으로 귀속하지 않았다.
