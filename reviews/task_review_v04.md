## 2. 미해결 사항

### M-01 — 새 Phase 2.5에 앱 E2E·Pages 배포 공통 절차가 그대로 적용된다

- **위치:** 0.1절 26~27행, 0.3절 46~55행, Phase 2.5 246~258행.
- **문제:** 공통 규칙은 모든 phase에 타입·린트·단위 검사와 phase E2E → main 배포 → smoke를 요구한다. Phase 0·1·4에는 예외/대체 절차가 있지만 새 Phase 2.5에는 없다. T2.7의 렌더 검사는 명시됐으나 그 검사로 앱 E2E를 대체하는지, 영상 완료 때도 앱을 main 배포하는지 정의되지 않았다.
- **영향:** 앱을 바꾸지 않는 영상 phase가 Phase 3과 병렬인데도 별도 앱 배포를 요구하게 된다. 동일 dev에서 Phase 3 후보가 준비되기 전에 영상 완료를 이유로 main에 올리거나, 명시되지 않은 영상 E2E를 기다리는 해석이 가능하다.
- **최소 수정:** Phase 2.5는 영상 프로젝트 검사·렌더·영상 인수로 종료하고, 앱 Playwright/Pages 배포 게이트와 분리한다고 명시한다. video/ 코드의 dev 커밋·검토는 기존 규칙을 유지하되, 영상 완료가 앱 main 배포를 촉발하지 않도록 한다.
- **닫힘 기준:** T2.7을 Phase 3 진행 중 완료해도 미검증 앱 코드를 배포할 필요가 없고, 무엇을 검사하면 영상 task를 체크하는지 단독으로 판정할 수 있어야 한다.

### M-02 — 병렬 제작의 입력 버전과 최종 교정 후 녹화 갱신이 정의되지 않았다

- **위치:** 248행, 253~257행, Phase 4 T4.1a·T4.5.
- **문제:** app/을 수정하지 않는다는 이유로 병렬 실행하지만, app/src 컴포넌트를 직접 import하면 Phase 3에서 바꾸는 공유 UI·의존성의 영향을 받을 수 있다. Playwright 녹화본 방식이면 Phase 4에서 앱 콘텐츠를 고친 뒤 Remotion을 ‘다시 렌더링’하는 것만으로 기존 녹화 영상의 가격·문구가 바뀌지는 않는다. 완료 증거에는 사용한 앱 버전이나 녹화본 갱신 여부가 없다.
- **영향:** 검증된 Phase 2 화면으로 시작했다고 해도 최종 영상의 앱 버전을 식별하기 어렵고, 번역·메뉴 교정 후에도 예전 화면을 재렌더링한 MP4를 최종본으로 제출할 수 있다.
- **최소 수정:** 시작 시 Phase 2 통과 앱 커밋/빌드 또는 녹화본을 고정하고 결과 기록에 남긴다. Phase 4 변경 시 영향 장면을 새 앱 버전으로 다시 캡처하거나 고정 import 입력을 갱신한 뒤 렌더·표기 검토한다. 최종 시연 전 이 갱신본 확인을 T4.5 또는 T2.7 재체크에 연결한다. 새 독립 task를 늘릴 필요는 없다.
- **닫힘 기준:** 영상이 어떤 앱 버전에서 만들어졌는지 확인 가능하고, 고정 문장 번역이나 가격이 교정됐을 때 기존 녹화본 재사용으로 잘못 통과하지 않아야 한다.
