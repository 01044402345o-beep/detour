## L-01 판정

**판정: 타당, Low 유지.**

**근거 (판정 시점에 직접 확인함)**
- 커밋과 인덱스가 아직 없다. `git ls-files`는 0건이고, `dev` 브랜치에 커밋이 없다("does not have any commits yet").
- 그런데 `reviews/T0.1_files.txt`는 20개 경로를 적고 있다. 이 목록은 실제 인덱스에서 뽑은 결과가 아니라 사전 목록이다.
- task.md T0.1 완료 조건은 "첫 커밋 전 `git ls-files` 전체 목록을 남기고 허용 경로만 있음"이다. 지금 파일은 이 조건의 증거가 되지 못한다. 지적이 맞다.
- 미추적 파일은 판정 시점에 50건이다. 그중 `app/` 아래 29건(T0.2 결과물로 보임)과 `reviews/T0.1_r1.md`가 목록에 없다. 이 판정 파일도 새로 생겼다.
- `.gitignore`의 제외 규칙은 Codex 확인 결과대로 정상이다. 개인 자료(HWP·MP4·PDF·그림 폴더)는 모두 무시되어 미추적 목록에 나타나지 않는다. 실제 유출 위험이 아니라 증거를 확정하는 문제이므로 Low가 적절하다.

**수정 지침 (task.md 0.2절에 따라 stage·commit은 coordinator만 함)**

| 순서 | 누가 | 무엇을 |
|---|---|---|
| 1 | coordinator | 첫 커밋 범위를 정한다. 권장은 T0.1 단독이다. `.gitignore`, `README.md`, `prd.md`, `task.md`, `mockup/index.html`, `reviews/*.md`(`T0.1_r1.md`·`T0.1_r1_verdict.md` 포함), `reviews/T0.1_files.txt`가 대상이다. `app/`은 T0.2 커밋으로 미룬다. |
| 2 | coordinator | `git add -- <위 경로>`로 경로를 하나하나 지정해 stage한다. `git add .`·`git add -A`는 쓰지 않는다. |
| 3 | coordinator | `git ls-files > reviews/T0.1_files.txt`로 목록을 다시 만들고, `git add -- reviews/T0.1_files.txt`로 다시 stage한다. 경로 집합이 바뀌지 않으므로 내용은 안정된다. |
| 4 | coordinator | `git ls-files`와 `reviews/T0.1_files.txt`의 경로 집합이 같은지 확인한다(`diff`로 차이 0). 허용 경로 밖·`node_modules`·`dist`·`.env`·개인 자료가 0건인지도 확인한다(`git ls-files \| grep -Ev '^(app/\|prd\.md\|task\.md\|mockup/\|reviews/\|\.github/\|\.gitignore\|README\.md)'` 결과 0줄). |
| 5 | coordinator | 커밋한 뒤 Codex 재검토(R2)를 요청한다. 닫힘 기준은 Codex R1에 적힌 그대로다(실제 인덱스와 목록 일치, 허용 경로 밖 0건). |

## 참고 (미해결로 세지 않음, T0.1 완료 조건 관련)

- **원격 연결:** 판정 시점에 `git remote -v` 결과가 비어 있다. T0.1 본문의 "원격 `origin` 연결"과 완료 조건 "원격 push 성공"은 아직 수행되지 않았다. 검토 대상이 아니라 남은 작업이므로 결함으로 세지 않는다. coordinator가 위 5단계 뒤에 연결하고 push한다.
- **브랜치:** HEAD가 `dev`(커밋 없음)이고 `main`은 아직 없다. T0.1 본문 "`main`/`dev` 브랜치 생성"에 따라 첫 커밋 후 `main`을 만들어 함께 push해야 한다. Phase 0 배포 순서(task.md 0.3절)와 맞추려면 이 시점에는 `main`을 같은 커밋에 두기만 하고, Pages 배포는 T0.3 이후에 한다.
