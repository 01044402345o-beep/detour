## 2. 직접 실행한 검증

| 명령 | 결과 |
|---|---|
| `npm run build` | 성공: TypeScript 검사, Vite production build, SW 생성 |
| `npm run test` | 성공: 2개 파일 / 4개 테스트 통과 |
| `npm run lint` | 성공, 오류·경고 출력 없음 |
| `npm run typecheck` | 성공 |

새 `types.test.ts`는 미지원과 6개 실패 상태에서 showStaff가 총 7회, 재시도가 지원되는 실패 상태에서 retry가 총 6회 호출됨을 확인한다. 미지원의 retry 접근에는 `@ts-expect-error`가 있으며, 테스트 파일을 포함하는 타입 검사도 통과했다. 따라서 해당 접근이 계약상 금지되는 조건까지 확인됐다. 이 테스트는 어댑터의 실제 상태 전이나 라우팅을 검증한 것은 아니며 그 구현은 T1.5·화면 task 범위다.

수사 함수는 아직 T1.3 stub이지만 수정된 골격 테스트는 함수 본문을 호출하지 않는다. 향후 `한`·`일`을 정상 반환하는 구현으로 바뀌어도 현재 assertion과 충돌하지 않음을 코드에서 확인했다. 이번 재검토를 위해 수사 구현을 임시 교체하지 않았다.

## 3. 신규 문제·검토 범위

변경된 실패 계약, 계약 테스트, 골격 테스트와 task 문구 사이에서 새 모순이나 회귀를 발견하지 못했다. 데이터 모델·주문·채점·TTS 계약을 바꾼 수정도 아니다.

R1의 빌드 도구 audit 위험 판단은 유지한다. 이번 변경은 의존성 조정이 아니므로 audit를 반복 실행하지 않았다. 앞선 결론은 현재 신뢰된 빌드 입력에서의 제한된 가용성 위험이라는 뜻이며 모든 환경에서 위험이 없다는 보증은 아니다. 판정에 기록된 T3.1의 상위 패치 재확인은 후속 작업으로 남는다.

SW 등록·PWA 완성, 실제 음성 동작, 화면 E2E와 실기기 시험은 기존 담당 task에서 검증한다. 현재 T0.2 수정 검토의 **미해결은 0건**으로 종료할 수 있다.
