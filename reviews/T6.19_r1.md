## L-01 — 현재 명세에 삭제된 다음 정류장 자동 선택 규칙이 남음

- 위치: `prd.md:170` F-03, `prd.md:182` F-15, `DESIGN.md:110` 코스 줄. 보조 정리 대상: `app/src/store/useAppStore.test.ts:346` 테스트 제목.
- 근거: F-15는 여전히 “place_view는 코스 길찾기의 다음 정류장 판단에도 씁니다”라고 명시한다. DESIGN 코스 줄은 새 “처음 행선지는 항상 1번” 설명과 함께 “처음 선택은 방문 기록으로 정한 다음 정류장”, “처음 선택 = 다음 정류장”을 유지한다. F-03도 버튼 문구 조건에 “1번이 다음 정류장이자 행선지”라는 삭제된 개념이 남았다. 실제 `Course/index.tsx:150-153`은 저장된 유효 선택 또는 0번을 사용하고 `target === 0`만으로 시작 문구를 정한다. 같은 명세를 따라 구현하거나 시연을 준비할 때 서로 다른 동작을 기대하게 된다.
- 수정안: 현재 명세를 “유효한 선택이 없으면 1번, 선택한 곳은 유지; 행선지가 1번이면 Start with stop 1”로 통일하고 F-15에서 길찾기 자동 선택 용도를 삭제한다. DESIGN의 항상 보이는 고정 길찾기 버튼 설명도 팝업 안 버튼 설명으로 합친다. 저장소 테스트 제목은 “새로 열면 1번부터”로 정리한다. 과거 작업 이력까지 소급 수정할 필요는 없다.

## L-02 — 새 팝업 경계와 키보드 길찾기 도달을 회귀 테스트가 끝까지 검증하지 않음

- 위치: `app/e2e/s9-walk-pick.spec.ts:43-51`, `app/src/screens/Course/Course.test.tsx:497-524`.
- 근거: S9는 Tab 한 번 뒤 초점이 팝업 내부에 있다는 것만 확인한다. 길찾기 링크에 `tabIndex={-1}`이 들어가는 변이는 통과할 수 있다. 단위 테스트는 Google 링크의 주소·문구를 확인하지만 가시성이나 팝업 밖 배치를 확인하지 않으므로, Google 링크를 hidden 팝업 안으로 옮겨도 해당 검증은 통과할 수 있다. 현재 구현 자체에는 이 두 문제가 없지만 이번 요구의 핵심 경계를 보호하지 못한다.
- 수정안: E2E에서 토글을 키보드로 펼치고 토글 초점 유지 → 선택된 라디오 → 길찾기 링크까지 Tab 순서를 검증한다. 접힌 상태에서도 Google 링크가 보이고 `walk-panel`의 자손이 아님을 검증한다. 가능하면 펼침/접힘 후에도 같은 조건을 확인한다.

## 확인 결과

- 초기 행선지: 두 코스 모두 유효한 저장 선택이 없으면 0번. 방문 이벤트 구독과 nextStop 호출은 제거되었고 삭제 파일을 참조하는 실행 코드가 남지 않았다. 기존 선택이 있으면 유지하는 것은 명세에 부합한다.
- 유지·초기화: `walkPicks[course.id]`로 상세 왕복·코스별 선택을 유지한다. 저장소 `resetData`는 모든 선택을 비우고 영속 저장 대상에서도 제외한다. 설정을 거친 화면 재진입은 새 컴포넌트에서 접힌 상태로 시작한다.
- 지도 목적지: Google 링크는 본문에 남고 네이버 버튼은 팝업 안에 있다. 둘 다 같은 `nextPlace`를 사용하며 문구·번호도 같은 target에서 나온다. 1번을 다시 고르면 Start with stop 1로 돌아오는 코드와 테스트가 있다.
- 접근성: 토글 이름·설명 ID가 분리되고 aria-controls는 hidden 컨테이너 ID를 가리킨다. legend의 sr-only는 접근성 이름을 보존한다. 펼칠 때 강제 초점 이동 없이 토글 초점을 유지하는 disclosure 구성이고 DOM 순서는 토글 → 라디오 그룹 → 링크다. 숨긴 팝업은 display:none이므로 키보드 대상에서 빠진다. 모달이 아니므로 초점 가두기는 필요하지 않다.
- 대비·크기: 토큰 #1d5bd6 위 흰색 대비를 계산하면 5.97:1, opacity 0.92 안내는 합성색 기준 5.31:1이다. 펼친 안내는 #55627a/흰색이다. 토글 최소 58px, 라디오 선택 칸 최소 44px, 길찾기 링크 54px이다.
- CSS: sticky bottom:0과 flex column, 패널 order:-1로 위쪽 확장 구조를 유지한다. 닫힌 dock 높이는 버튼+패딩+테두리로 줄었다. 등장 애니메이션은 패널에 적용하고 hidden 상태는 즉시 숨긴다. reduced-motion은 패널·화살표뿐 아니라 전역 선택 칸 transition도 끈다. 실제 높이·확대/낮은 화면 배치는 이번 검토에서 브라우저 재측정하지 않았다.
- 삭제 파급: Place의 Next는 `place.order + 1`에 따른 코스 순서 안내라 방문 기록 기반 선택과 별개이며 유지 가능하다. 현재 `deck/index.html`에는 삭제한 자동 선택 동작 설명을 찾지 못했다.
- i18n: 세 언어 패치 키와 최종 사전 값이 일치한다. `$override`는 패치 안에 있는 `course.pickHint`만 지정하며 스크립트의 허용 규칙에 맞는다. 읽기 전용 `node app/scripts/i18n-patch.mjs app/src/i18n/patches/T6.19.json --check` 결과는 `up to date`였다.
- 검증 범위: 기존 단위 테스트는 두 코스의 기록 유무, 선택 변경, 상세 왕복, 초기화, 접근성 이름, 목적지 일치를 다룬다. S9는 두 코스의 팝업/버튼 좌표를 검증한다. `git diff --check HEAD`는 오류 없이 완료했다. 테스트 감소 자체는 삭제한 기능 테스트 제거로 설명되며 결함으로 판단하지 않는다.
