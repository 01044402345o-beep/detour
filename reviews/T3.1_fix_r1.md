## M-01 — 저장 불가 상태에서 업데이트 새로고침 생략

- 판정 지침의 두 선택지 중 **"토스트는 띄우고, '업데이트'를 누르면 교체·새로고침 없이 닫기"**를 골랐습니다. 대기 중인 새 워커는 다음에 앱을 다시 열 때 적용됩니다. 새 사전 문구는 없습니다.
- `canPersist()`: `localStorage`에 `__detour_pwa_probe__`를 썼다 지워 봅니다. `localStorage` 접근 자체가 예외이거나, 쓰기가 예외면 false. `safeStorage`의 probe와 같은 방식이며 store는 건드리지 않습니다.
- 판단 시점은 버튼을 누를 때입니다. 방어 범위는 localStorage 접근 차단과 탐지 key 쓰기 실패이며, 앱 스냅숏만 용량 초과로 실패하는 경우는 막지 않습니다(T3.1 R2 판정에서 제한으로 수용).
- 회귀 테스트
  - `pwa.test.ts`: 저장 가능 → `updateSW(true)` 호출(기존 테스트), **저장 불가(`Storage.prototype.setItem` 예외 주입) → `updateSW` 호출 없음 + 토스트 닫힘**(신규)
  - `canPersist.test.ts`(신규 3건): 정상 → true·탐지 key 남기지 않음 / `setItem` 예외 → false / `localStorage` getter 예외 → false
