# T1.2 다국어 사전 R2 — Codex

2026-11-23. R1 판정의 M-1·M-2·L-1·L-2는 모두 해소됐다. `formatKo`가 template 대신 key를 받는 변경도 타당하다. 구현과 맞지 않는 API 안내 주석 1건이 새로 남아 있다. 앱 소스·테스트·기존 문서는 수정하지 않았다.

M-2에서 한 단어 영어 배열과 동적 조합은 판정에 따라 Phase 2 E2E로 이관된 제한이다. 이 경로가 여전히 검사에 통과한다는 이유로 재개방하지 않는다. data/domain 경로 예외 유지 역시 판정 범위에 맞다. 운영자 상수와 정확히 같은 리터럴이 허용되는 것은 문자열 허용 목록을 쓰라는 판정에 따른 동작이며, 임의의 `운영자 리포트`는 계속 위반으로 잡힌다.

## 판정과 다른 구현의 타당성

`formatKo(key: OperatorKoKey, params?: Params)`는 공개된 운영자 키만 받으므로 호출 실수를 타입 검사로 줄이고, 경고에 `OPERATOR_KO.deviceEvents`처럼 키를 남길 수 있다. 내부에서 동일한 `fillTemplate`을 사용하므로 template 기반 지침의 치환·누락 경고·영어 fallback 없음 요구를 보존한다. 아직 소비 화면이 없어 기존 호출부 호환성 문제도 없다. **key 기반 구현을 승인할 수 있다.**

문장형 검사에서 `[공백/NBSP]` 대신 `\s`를 사용한 변경은 줄바꿈·탭까지 검사하는 확장이며 린트와의 충돌 회피 근거가 있다. template 조각 대신 전체 문장을 판별하는 보강도 `Saved ${n} items.`의 누락을 막으므로 타당하다.

## R2-L-01 — formatKo 사용 안내가 이전 template 기반 API로 남음

- **위치:** `app/src/i18n/operatorKo.ts:6` (실제 함수는 `:48`).
- **문제:** 머리 주석은 `formatKo(template, params)`로 안내하지만 함수는 `formatKo(key, params)`를 받는다. 화면 담당자가 `formatKo(OPERATOR_KO.deviceEvents, { count: 3 })`처럼 주석대로 작성하면 타입 오류가 난다.
- **근거:** 위 key 기반 API 변경은 정당하지만 사용 지침까지 갱신되지 않았다. 현재 런타임 소비자가 없고 타입 검사로 발견되므로 Low다.
- **권장 수정:** 주석을 `formatKo(key, params)`로 바꾸고 `formatKo('deviceEvents', { count: 3 })` 예를 적는다. 동작 변경이나 추가 테스트는 필요 없다.
