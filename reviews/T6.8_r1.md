# T6.8 코드 검토 R1

검토일: 2026-11-26. 지정된 변경 파일의 git diff 및 신설 파일, 연결된 라우터·언어 화면·저장소·PWA 코드를 읽고 검증했다. 소스 수정·커밋·푸시는 하지 않았다. 직접 작성한 파일은 이 보고서뿐이며, 허용된 검사 실행에 따른 빌드·테스트 산출물은 발생한다.

## 판정

**H 0 / M 0 / L 2.** coordinator가 명시한 ‘홈 문서 새 로드 시 인트로, 언어 선택 완료 사용자의 딥링크 유지’ 범위에서는 차단할 기능 결함을 발견하지 못했다. 아래 문서 정확성과 테스트 보강 사항은 남아 있으므로 ‘검토 미해결 0’으로 기록하면 안 된다.

## 지적 사항

### L-01 — 문서의 딥링크 예외 조건과 결정 주체를 정확히 적어야 함

- 위치: `prd.md:150`, `DESIGN.md:87`, `task.md:443`, `app/src/router/launchIntro.ts:2` 및 `:4`.
- 문서는 특정 화면 주소로 열면 그대로 열린다고 쓰지만, `AppRoutes.tsx:89`는 언어 미선택 사용자를 어느 주소에서든 `/lang`으로 보낸다. 이후 시작 버튼은 원래 주소가 아닌 홈으로 이동한다. 신규 사용자가 장소 QR을 처음 열면 문서와 달라지는 구체적인 경우다. 이는 기존 동작 유지이며 이번에 새로 생긴 회귀는 아니다.
- 제공된 사용자 원문은 ‘인트로 화면이 항상 나오도록 해줘’이고 홈 한정·딥링크 예외는 coordinator의 해석이다. 문서에서 예외까지 ‘사용자 결정’으로 묶으면 합의 근거를 과장한다.
- 권고: ‘사용자 요청에 따라 홈을 새로 불러올 때마다 표시하도록 구현. 언어 선택을 완료한 사용자의 특정 화면 주소는 유지하며, 언어 미선택 시 기존처럼 인트로 → 홈’으로 명시한다. 기존 PWA 창 재개·BFCache 복원은 새 로드가 아니므로 재표시하지 않는다는 경계도 짧게 적는다. 이 지적은 추가 승인 요청이 아니라 현재 구현 범위의 정확한 기록을 요구한다.

### L-02 — 전역 테스트 기본값 때문에 실제 새 실행의 계측·StrictMode 계약은 검증되지 않음

- 위치: `app/src/test/setup.ts:5`, `app/src/router/AppRoutes.test.tsx:85`, `app/e2e/s8-launch-intro.spec.ts:6`.
- 전역 `beforeEach`가 pending을 false로 만들어 기존 라우터·화면 테스트는 ‘이미 최초 진입 판단을 끝낸 페이지’를 검사한다. 테스트 간 모듈 상태 누수는 막지만 신규 통합 테스트도 별도 설정 없이는 실제 새 실행을 검사하지 않게 된다.
- 전용 테스트 3개가 true를 복원하고 S8이 실제 브라우저 모듈 초기화까지 확인하므로 핵심 기능 전체를 가리는 상태는 아니다. 다만 true인 테스트에는 `screenViews()` 검증이 없고, 단위 테스트는 StrictMode로 감싸지 않는다. production preview E2E는 개발 StrictMode의 effect 재실행을 검증하지 못한다.
- 권고: true + StrictMode인 라우터 테스트에서 인트로 → 시작 → 홈의 이벤트가 정확히 `['lang', 'home']`인지 검사한다. 실제 시작 버튼과 뒤로가기, 해시 없는 `/edulleo/` 진입, 오프라인 홈 재로드를 보강하면 요청된 경계 사례까지 명시적으로 잠근다. 화면별 테스트는 false를 쓰는 이유를 fixture에서 드러내는 편이 좋다. 현재 확인된 중복 계측 버그를 주장하는 것은 아니다.

## 요청한 경계 사례 검토

| 경우 | 판정·근거 |
|---|---|
| 홈 주소와 모든 주소 진입의 구분 | 홈 진입을 일반 실행으로 보고 딥링크를 보존하는 해석은 합리적이다. 다만 원문의 유일한 해석은 아니며, 모든 진입마다 표시하는 구현은 아니다. |
| PWA 아이콘 | manifest의 start_url은 `/edulleo/`이고 HashRouter는 해시 없는 주소를 `/`로 해석하므로 새 문서 실행은 인트로 대상이다. 이미 살아 있는 문서를 재개하면 모듈 pending은 false 그대로다. 실제 설치 PWA 재개는 이번 자동 검증에 포함되지 않는다. |
| QR·특정 화면 주소 | 저장된 언어가 있으면 특정 화면으로 바로 열리고 이후 홈 이동도 허용한다. 언어 미선택 예외는 L-01 참조. |
| 오프라인 | SW는 앱 셸과 lazy 청크를 프리캐시한다. 기존 P3 E2E에서 설정·장소·문장·코스의 오프라인 새로고침이 모두 통과했다. 오프라인 홈 → 인트로는 코드상 같은 경로지만 전용 실행 검증은 없다. |
| 첫 실행 | lang null 우선 가드가 유지되며 기본 EN·언어 선택·시작 → 홈 흐름의 기존 테스트가 통과했다. |
| 시작 후 뒤로가기 | 가드 이동과 LangScreen의 시작 이동 모두 replace이므로 인트로 항목을 추가로 남기지 않는다. 이전 앱 내 항목으로 돌아갈 때 pending은 false다. 브라우저 실제 뒤로가기 전용 테스트는 없다. |
| StrictMode | render는 pending을 읽기만 하고 effect의 false 대입은 멱등이다. 코드상 이중 실행으로 인트로를 반복시키는 명백한 경로는 발견하지 못했다. 이중 effect 실행 직접 검증은 L-02의 공백이다. |
| 모듈 상태·HMR | 일반 문서 재로드는 true로 초기화되고 같은 문서에서는 false를 공유하는 의도다. 테스트는 매 테스트 false로 리셋한다. 해당 모듈을 HMR로 재평가하면 true로 돌아갈 수 있으므로 개발 중 편집 상태까지 ‘한 페이지에서 한 번’을 보장한다고 해석하면 안 된다. 배포 회귀는 아니다. |
| screen_view | 홈 가드가 Navigate를 반환할 때 logger를 렌더하지 않으므로 숨겨진 홈을 먼저 기록하지 않는다. 인트로에서 logger가 마운트되고 이후 경로 key로 중복을 막는 기존 구조를 유지한다. true 상태에서 이벤트 수를 잠그는 테스트는 추가 권고다. |
| 기존 E2E 계약 | openHome은 인트로 또는 홈을 기다린 뒤 필요 시 시작한다. S5 언어 전환·S6 제보 수 검증을 유지하며 전체 E2E가 통과했다. S8이 별도로 인트로 필수 표시를 단언하므로 helper의 선택적 처리가 신규 계약의 유일한 검증은 아니다. |
