## 지적 사항

### M-01. 새 앱 캡처 속 사진의 출처·변경 이력을 PDF에서 확인할 수 없음

- **쪽:** 엑셀러레이팅 PDF 4쪽(본문 2쪽) 앱 그림, 인큐베이팅 PDF 4쪽 그림 1 및 7쪽 그림 4.
- **근거:** 새 그림에는 성심당 사진, 홈의 중앙시장·으능정이 사진 및 코스 썸네일 등이 들어간다. 확대하면 성심당 화면 안에 `Photo: Trainholic · CC BY-SA 4.0`이라는 짧은 글씨는 있으나, PDF 캡션·본문에는 사진별 원본/라이선스 링크와 변경 내역이 없다. 홈 캡처는 화면 아래 출처 영역이 보이지 않는다. 인큐베이팅 7쪽의 ‘장소 사진 11(출처 표기)’는 앱 설명일 뿐 PDF 독자가 출처를 찾아갈 수 있는 안내가 아니다. `plan.html`·`doc.html`·`t615/figs.html`에도 해당 출처 연결이 없다.
- **대조:** `app/src/data/photos.ts`에는 저작자·원본 URL·라이선스·원본 고지·얼굴 흐림/리사이즈/WebP 변경 이력이 있고, PRD 4.0·10장은 출처와 변경 내역 표시를 요구한다. CC BY-SA 4.0 공식 안내 역시 적절한 저작자 표시, 라이선스 연결, 변경 표시를 명시한다. [Creative Commons 공식 안내](https://creativecommons.org/licenses/by-sa/4.0/)
- **수정안:** 그림 옆 또는 문서 말미에 **이 PDF 캡처에 실제 등장한 사진**의 출처표를 넣는다. 사진/저작자/원본 링크/라이선스 링크/원본 고지/변경 이력을 표시하거나, 이 정보를 보존한 공개 출처 페이지로 명확히 연결한다. 운영자 직접 촬영 사진과 CC 사진은 구분하고, 사진에 적용되는 라이선스임을 밝힌다. 앱 설정 안의 출처 시트만으로 PDF의 출처 안내를 대신하지 않는다. 이는 출처 보완 지적이며 원본 사진의 무단 사용을 단정한 것은 아니다.

### M-02. ‘전 화면 오프라인·최신본 E2E’가 실제 확인 범위보다 넓음

- **쪽:** 엑셀러레이팅 PDF 4쪽(본문 2쪽) 기능 설명, PDF 5쪽(본문 3쪽) 상품 완성도 카드.
- **근거:** 4쪽은 ‘한 번 접속 후 … 코스·사진·메뉴·문장 화면 사용(최신본 자동 점검)’, 5쪽은 ‘오프라인 사용 / 전 화면 / 네트워크 차단·최신본 E2E’라고 표시한다. 바로 아래 각주는 ‘오프라인 E2E는 원도심 경로, 시장 경로 E2E는 추가 예정’으로 제한해 큰 카드와 범위가 맞지 않는다.
- **코드:** `app/e2e/p3-offline.spec.ts`는 **설정의 오프라인 준비 완료를 기다린 뒤** 차단한다. 원도심 장소 4곳의 화면·확인 배지·탭, 성심당 담기, 문장 모음, 원도심 SVG 약도를 검사한다. 시장 경로·모든 화면·사진의 실제 디코딩/표시를 전수 확인하는 테스트가 아니다. `vite.config.ts`의 WebP 사전 캐시 설정은 구현 근거지만 화면별 오프라인 성공을 모두 실측했다는 근거와 다르다. PRD 7·10장도 캐시 완료 확인과 음성의 기기 의존성을 구분한다.
- **수정안:** 큰 카드를 ‘오프라인 기본 화면 / 원도심 경로 E2E 확인’으로 바꾸고, 4쪽은 ‘설정의 **오프라인 준비 완료 후**, 약도·사진·메뉴·문장 제공(사전 캐시 구현, 원도심 경로 E2E 확인)’으로 쓴다. 시장 경로·사진 표시 전수 검증은 미확인으로 분리하고, 외부 지도·음성까지 오프라인 보장으로 읽히지 않게 한다. 새로운 검증을 했다면 해당 결과와 대상 빌드를 먼저 기록한다.

### L-01. 인큐베이팅의 1,242건은 합계 성격과 기준일이 빠짐

- **쪽:** 인큐베이팅 PDF 3·7·10쪽, 중심 위치는 7쪽 기능·품질 항목.
- **근거:** 세 곳 모두 ‘자동 테스트 1,242개’만 적혀 있다. 종전 859개는 단위 테스트 수였고, 이번 1,242개는 **Vitest 1,161 + Playwright E2E 81**의 합이다. 엑셀러레이팅 PDF 5쪽은 이 구성을 분리했으나 인큐베이팅에는 분해·기준일이 없다. `app/playwright.config.ts`상 E2E는 언어·뷰포트별 반복 실행과 음성 목을 포함하므로 1,242개의 독립 사용자 기능 또는 실기기 음성 성공 사례를 뜻하지 않는다.
- **수정안:** 인큐베이팅 7쪽에 ‘자동 테스트 1,242건(Vitest 1,161 + E2E 81, 2026.11.26·7643986 기준 기록)’을 한 번 밝힌다. 필요하면 ‘E2E는 언어·화면 크기별 실행 포함, 음성 목 사용’이라는 각주를 붙인다. 다른 두 곳은 간단한 합계를 유지해도 된다. 합계 자체가 틀렸다는 지적은 아니다.

### L-02. ‘열 때마다 인트로’에 홈 진입 조건이 빠짐

- **쪽:** 인큐베이팅 PDF 7쪽 형태 설명.
- **근거:** ‘열 때마다 인트로’는 특정 화면 주소로 바로 열거나 해당 화면을 새로고침해도 인트로가 나온다는 의미로 읽힌다. `app/src/router/AppRoutes.tsx`의 `LangGate`는 언어 미선택 때 모든 경로를 언어 화면으로 보내지만, 언어 선택 후에는 `isLaunchIntroPending() && pathname === PATHS.home`일 때만 인트로를 띄운다. PRD 3.1도 ‘페이지를 새로 불러와 홈에서 시작하면 매번 표시’라고 한정한다.
- **수정안:** ‘새로 열어 **홈에서 시작할 때** 인트로’로 변경한다.

### L-03. 이용 기록을 ‘화면 열람 기록뿐’으로 축소 서술

- **쪽:** 인큐베이팅 PDF 7쪽 한계 설명. 기존 문구가 이번 갱신에도 남았다.
- **근거:** `app/src/domain/events.ts:12`의 이벤트는 `screen_view`, `place_view`뿐 아니라 `phrase_play`, `practice_done`, `staff_shown`, `report_sent`도 포함한다. PRD F-15 역시 이들을 기기 안에 기록한다고 설명한다. ‘실제 방문 확인 불가’라는 결론은 맞지만 기록 종류 설명은 현재 코드와 다르다.
- **수정안:** ‘이용 기록은 **화면 열람·문장 듣기·연습 등 기기 내 사용 기록이며 실제 방문 증거는 아님**’으로 쓴다. 현재 서버 집계나 실제 방문 체크가 구현됐다는 인상을 주지 않는 기존 구분은 유지한다.

### L-04. 말하기 연습 캡처를 주문 카드 단계로 표시

- **쪽:** 인큐베이팅 PDF 7쪽 그림 4의 ④, `t615/figs.html`의 `s04.png` 캡션.
- **근거:** 실제 캡처에는 마이크, `Tap the mic and say it out loud`, 상단 진행 표시가 보이며 사용자 제공 `앱화면/04_말하기연습.png`에 해당한다. PRD의 `/order` 주문 카드와 `/practice` 말하기 연습은 다른 화면이다. 그림은 ④를 ‘한국어 주문 문장’이라고만 써서 실제 주문 카드 화면으로 오해할 수 있다. 엑셀러레이팅의 그림 아래 긴 캡션은 이미 ‘한국어 주문 문장·말하기 연습’으로 설명한다.
- **수정안:** 인큐베이팅 ④를 ‘한국어 주문 문장·말하기 연습’ 또는 ‘주문 문장 말하기 연습’으로 바꾼다. 꼭 주문 카드 단계가 필요하면 실제 `/order` 캡처로 교체한다.
