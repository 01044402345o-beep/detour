# PRD v0.1 검토 R1

- 검토일: 2026-11-23. 대상: `prd.md` 1~239행.
- 참고: `참가신청서_개편안/HWP_배치원고.md`, `대전디투어_원본/screens.html`. 작성 중인 `mockup/`은 열람·검토하지 않았다.
- 문서 요구사항 검토이며 구현 결함을 판정한 것은 아니다. 현장 확인을 수행하지 않았으며, 최신 판매 조건·권리 관계 등 확인하지 못한 사항은 아래에 **확인 필요**로 명시했다.

## High

### H-1. 광천식당 소재 동이 공식 안내와 다름

- **위치:** 4장 77~85행, 8.1절 193~199행.
- **문제:** 광천식당을 ‘대흥동’으로 기재했으나 대전시 공식 안내는 ‘선화동’이다. 실제 장소를 안내하는 핵심 데이터의 사실 오류다.
- **근거:** [대전시 전통업소 안내](https://www.daejeon.go.kr/fod/fodTraditionList.do?menuSeq=161&pt=tradition&searchAdG=ADG05)는 광천식당 주소를 중구 대종로505번길 29(선화동)로 제시한다. PRD의 도보 시간·약 2km가 틀렸다고까지 확인한 것은 아니다.
- **권장 수정안:** 소재 동을 공식 주소와 맞추고 전체 주소·좌표를 확정한다. 이 좌표로 정류장 순서, 구간별 도보 시간, 총거리를 재검증한다. 최신 영업 장소와 실제 보행 경로는 **확인 필요**다.

### H-2. 사업 모델 시연의 필수 결과가 선택 기능으로 분류됨

- **위치:** 1.2절 25행, 3.1절 60~61행, F-13~F-16 133~136행, S11·S13 156~158행.
- **문제:** 목표와 In scope는 운영자 리포트 시연을 요구하지만 F-16은 선택이다. 저장·제보도 포함 범위와 기능 우선순위가 다르며, 리포트의 ‘내 기기 기록’은 선택인 F-15에 의존한다. 필수 기능만 구현해도 문서상 완료 처리되면서 사업 모델 시연은 빠질 수 있다.
- **근거:** 25행은 운영자 리포트로 사업 모델을 보여준다고 명시한다. F-16의 예시 데이터 표시는 적절하지만 구현 자체의 우선순위 모순은 해소하지 못한다.
- **권장 수정안:** 최소 예시 리포트와 진입 경로를 필수로 지정한다. 로컬 실측 기록·제보 연동은 별도 선택 단계로 분리하거나 의존 기능까지 필수화한다. S11·S13에도 필수/선택 및 미구현 시 메뉴 노출 규칙을 맞춘다.

### H-3. 심사위원 개인 기기에서 음성 성공을 보장하는 조건이 상충함

- **위치:** 1.2~1.3절 21~34행, 2장 45행, F-07~F-09 127~129행, 7장 167~171행, 10장 231~233행.
- **문제:** 개인 휴대폰의 TTS 동작과 따라 말하기·채점을 목표로 하지만, 한국어 음성이 없으면 안내만 표시하고 시연 기기 사전 점검은 안드로이드 중심이다. 미지원·권한 거부 외에 무음, 네트워크 오류, 결과 없이 종료되는 경우의 종료 시간도 없다. HTTPS만으로 음성 엔진과 한국어 음성이 확보되지는 않는다.
- **근거:** [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)은 지원 범위가 제한적이고 서버 인식이 사용될 수 있음을 설명한다. [MDN getVoices](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)는 기기에서 이용 가능한 음성 목록을 반환하며 음성 목록 변경 처리 예제를 제공한다. PRD의 ‘TTS 동작’ 합격 기준과 ‘없으면 안내’는 같은 성공 상태가 아니다.
- **권장 수정안:** 검증된 진행자 기기의 전체 음성 시연과 심사위원 개인 기기의 텍스트 완주를 구별해 합격 기준을 정한다. 사용자 탭 시작, 한국어 음성 목록 초기화, 재생 오류, 인식 타임아웃·취소·무음·네트워크 실패 상태를 정의하고 모든 상태에서 주문 카드로 즉시 이동시킨다. 녹음/재생을 화면 이탈 시 정리한다. TTS가 반드시 필요한 대표 문장은 권리가 확보된 사전 음원 대체를 검토한다. 실제 iOS/Android의 버전별 동작은 **확인 필요**다.

### H-4. 음성 비저장·서버 없음 문구가 외부 음성 처리와 구별되지 않음

- **위치:** F-08 128행, F-15 135행, 7장 169행, 8장 184행.
- **문제:** ‘Audio is not saved’, ‘음성은 저장하지 않고’, ‘서버 없음’만으로는 앱이 음성을 보관하지 않는다는 뜻과 브라우저 제공자의 외부 처리·보관 여부가 구분되지 않는다. 앱 구현만으로 제3자의 미보관을 보장할 수 없다.
- **근거:** [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)은 일부 브라우저의 기본 인식이 음성을 웹 서비스로 전송한다고 명시한다. 이는 자체 서버가 없다는 아키텍처와 양립하지만 포괄적 비저장 보장과는 다르다. 실제 제공자·보관 조건은 **확인 필요**다.
- **권장 수정안:** ‘이 앱은 음성과 인식 내용을 저장하지 않습니다. 브라우저 음성 서비스에서 처리될 수 있습니다’처럼 앱 통제 범위를 명시하고 EN/JA/ZH로 제공한다. 마이크 사용 전에 설명하고 텍스트 경로를 제공한다. 인식 원문을 이벤트·오류 로그에 남기지 않는 규칙, 로컬 기록의 필드·보존 기간·초기화 범위를 정한다. 법적 고지·동의 필요성은 실제 데이터 흐름 확정 후 별도 확인하며 여기서 위법 여부를 단정하지 않는다.

### H-5. ‘한 번 접속’만으로 오프라인 완주를 보장하는 조건이 없음

- **위치:** 1.3절 34행, 7장 166행, 8장 183행, 10장 232행.
- **문제:** 첫 페이지 방문과 필요한 자산 전체의 캐시 완료는 다르다. 아직 열지 않은 메뉴·언어 사전·코스 데이터·분할 JS가 남을 수 있다. 처음 QR로 들어오는 심사위원 기기는 네트워크 단절 시 캐시 자체가 없다. OSM 타일과 음성 서비스도 앱 캐시만으로 오프라인화되지 않는다.
- **근거:** [MDN Service Worker 사용 안내](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)는 설치·활성화·캐시 처리를 별도 과정으로 설명한다. [OSMF 타일 정책](https://operations.osmfoundation.org/policies/tiles/)은 표준 타일의 대량 다운로드·사전 가져오기 및 오프라인 다운로드 기능을 허용하지 않는다. SVG 약도 병행 결정 자체는 적절하다.
- **권장 수정안:** 앱 셸·3개 언어·전체 원도심 JSON·SVG 약도의 캐시 목록과 ‘오프라인 준비 완료’ 조건을 지정한다. OSM 타일을 오프라인 프리캐시에서 제외하고 지도 실패 시 약도로 전환한다. 준비된 기기에서 네트워크 차단 후 재접속·미방문 화면 진입을 시험한다. 신규 QR 접속에는 행사장 연결/예비 네트워크가 필요함을 시연 조건에 넣고 진행자 기기의 사전 준비와 구분한다.

## Medium

### M-1. 실제 주문 단위와 가능한 조합을 검증·표현할 계약이 부족함

- **위치:** 4.1절 89~105행, F-05~F-06 125~126행, S05 150행, 8.1절 195~197행.
- **문제:** ‘인분’ 판매, ‘칼국수 사리’의 실제 명칭·단위, 최소 주문량, 단독 추가 주문 가능 여부가 확정되지 않았다. 매장 식사만 가능하다는 설명과 S05의 공통 포장 전환 사이에도 조건이 없다. `takeout`만으로는 매장 이용 가능 여부나 쟁반 셀프 선택 방식을 충분히 표현하지 못한다.
- **근거:** PRD 스스로 현장 확인 전 예시라고 밝힌다. [대전시 소개 기사](https://www.daejeon.go.kr/its/ItsdjNormalboardView.do?boardGubun=itsdj01&boardSeq=2866)는 광천식당 두루치기에 ‘우동 사리’를 소개해 PRD와 용어가 다르다. 이 기사만으로 현재 메뉴가 잘못됐다고 단정하지 않으며 최신 메뉴·가격·포장·맵기 조절 가능 여부는 **확인 필요**다.
- **권장 수정안:** 현장 메뉴판/점포 안내를 기준으로 판매 단위, 옵션, 최소·최대 수량, 추가 메뉴의 선행 조건을 확정한다. 필요하면 접시·그릇·세트 등 실제 판매 단위를 모델에 추가한다. 허용하지 않는 포장 옵션은 비활성화하고, 빵집 카드는 실제 셀프 선택 절차를 대체하지 않는다는 사용 시점을 표시한다. 미검증 메뉴는 실제 주문용 시연에서 제외한다.

### M-2. 수사 기본 규칙은 맞지만 생성 문법의 경계 조건이 빠짐

- **위치:** F-05~F-06 125~126행, 8.1절 197~198행.
- **문제:** 한/두/세 및 인분의 한자어 수사 구분만으로는 여러 메뉴, 수량 4 이상, 빈 주문, 합계·번역·발음 표기가 일치하는지 판정할 수 없다. 수량 상한과 문장 결합 규칙이 없다.
- **근거:** [국립국어원 한국어기초사전 ‘인분’](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=70759&nation=eng)의 ‘일 인분’ 예시와 F-06은 일치한다. 따라서 인분을 고유어 수사로 고칠 사안은 아니다. 문제는 완전한 생성 규격 부재다.
- **권장 수정안:** 데모 수량을 예컨대 1~9로 제한하고 개·공기의 한/두/세/네/다섯… 및 인분의 일/이/삼/사…를 검수한다. ‘튀김소보로 두 개, 공기밥 한 공기 주세요’처럼 조사 선택이 필요 없는 결합 틀, 띄어쓰기, ‘주세요’와 포장 문장의 배치를 확정한다. 이 예시는 문법 설명이며 서로 다른 가게 메뉴를 함께 담는 허용 예시가 아니다. 0개 항목 제외·빈 주문 생성 금지·수량 변경 시 3개 언어와 발음 동시 갱신을 인수 기준으로 둔다.

### M-3. 일본어·중국어 발음 표기 정책과 한국어 유지 영역이 불완전함

- **위치:** 1.3절 32행, F-01 121행, F-08 128행, F-10~F-11 130~131행, 8.1절 197~198행, 11장 237행.
- **문제:** 중국어 간체 번역과 한국어 로마자 발음 안내는 다른 정보인데 로마자 체계가 정의되지 않았다. 메뉴에만 있는 `roman/kana`로 수사·단위·연결 문구까지 동적 생성할 정책도 없다. ‘모든 사용자 문구 전환’은 직원용 한국어 응답 버튼과 예외 범위가 모호하며 영어 고정 안내가 남을 수 있다.
- **근거:** PRD는 EN/ZH 로마자, JA 가타카나라는 큰 방향만 정한다. 원어민 검수 체크는 있으나 검수 대상·발음 근사 표기 한계·숫자 조합의 통과 기준은 없다.
- **권장 수정안:** 로마자는 한국어 발음 안내이며 중국어 병음이 아님을 구분하고 한 가지 표기 체계를 정한다. 가타카나는 근사 표기임을 알리고 메뉴·수량·단위·주세요·포장 문장의 검수된 조각을 조합한다. 사용자 UI·고유명사·직원 한국어 영역의 전환 예외를 명시하고 개인정보·오류·Coming soon까지 번역 목록에 포함한다.

### M-4. 받아쓰기 유사도와 발음 진단의 경계가 없음

- **위치:** F-09 129행, S07 152행, 8장 185행.
- **문제:** 인식 문자열의 편집거리는 실제 발음의 길이·억양을 측정하지 않는다. 점수 산식, 숫자/띄어쓰기 정규화, 단어 정렬, 빈 결과 처리, 팁의 근거가 미정이다.
- **근거:** PRD 입력은 음향 특징이 아닌 받아쓰기 결과다. 참고 정적 목업에는 발음이 짧았다는 진단과 직원이 알아들을 것이라는 확정 표현이 있으나 이 알고리즘으로 입증할 수 없다. 이 점은 목업 재사용 시 주의 사항이며 작성 중인 mockup의 결함을 뜻하지 않는다.
- **권장 수정안:** 점수 명칭을 ‘인식 문장 일치도’로 정하고 발음 정확도나 의사소통 성공을 보장하지 않는다. 한글 정규화, 공백·문장부호·‘2개/두 개’ 처리, 0~100 산식과 반올림, 단어 대응 규칙을 명시한다. 빈 인식은 0점 대신 재시도 상태로 처리하고 팁은 검수된 일반 연습 안내만 사용한다.

### M-5. 지도 경로선 데이터와 OSM 사용 조건이 빠짐

- **위치:** F-03~F-04 123~124행, 8장 183행, 8.1절 193~199행.
- **문제:** 정류장 좌표만 있고 실제 보행 경로선 데이터가 없다. 정류장 직선 연결을 보행 경로처럼 보일 가능성이 있다. ‘API 키 없음’은 타일의 무제한 이용이나 가용성 보장을 뜻하지 않는다.

### M-6. 영업 상태·확인일·알레르기 정보의 의미와 데이터가 부족함

### M-7. 상호 사용 점검의 완료 기준과 공개 범위가 불명확함
