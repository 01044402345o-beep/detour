# T3.1 수정 2회차 — '오프라인 준비 완료' 판정 견고화 (Phase 3 E2E 1회 실패 대응)

일자 2026-11-23. 근거: `reviews/phase3_e2e.md` — `[m360] P3 오프라인 [en]`에서 설정 화면은 열렸지만 `offline-ready` 카드가 30초 동안 안 보임(누적 480회 중 1회, 이후 재현 0회, trace 없음).
수정 범위: `app/src/sw/`, `app/src/screens/Settings/`의 오프라인 표시 부분과 테스트. store·사전·공용 UI 변경 없음.

## 1. 원인 분석 (수정 전 `pwa.ts`)

준비 판정(`refreshOfflineReady`)은 **세 이벤트(onRegisteredSW·onOfflineReady·controllerchange) 때만** 돌았고, 재시도가 없었습니다. 다음 중 하나라도 일어나면 이후 이벤트가 더 오지 않아 카드가 영영 안 뜹니다.

| # | 경로 | 수정 전 결과 |
|---|---|---|
| a | 세 이벤트가 모두 "페이지가 아직 워커 제어 전"(controller 없음)에 판정 → `null`(보류). 그 뒤 제어가 넘어왔는데 controllerchange를 이미 지나친 순서 | 보류인 채 끝 |
| b | 판정 하나가 멈춤 — `navigator.serviceWorker.ready`·활성화 대기는 시간 제한이 없었고(응답 대기만 5초 제한), 부하가 큰 병렬 실행에서 워커 응답이 5초를 넘기면 `null` | 보류인 채 끝 |
| c | 판정 여러 개가 겹쳐 돌다가 늦게 도착한 옛 응답(예: 51/52)이 새 판정(52/52)을 덮어씀 | 거짓으로 덮임 |

E2E 1회 실패의 trace가 없어 어느 경로였는지 단정할 수는 없습니다. 세 경로를 모두 막았습니다.

## 2. 수정

| 파일 | 내용 |
|---|---|
| `app/src/sw/pwa.ts` | ① **간격 재확인**: 준비 전이면 판정이 끝날 때마다 다음 확인을 예약(1·2·3·5초, 이후 5초 반복, 최대 60회(대기 간격 합계 약 5분, 판정마다 최대 8초가 더해져 최악 약 13분, 백그라운드 탭에서는 더 길어질 수 있음)). 준비되면 멈춤. ② **한 번에 하나만**: 판정 중에 다시 불리면 끝난 뒤 최신 상태로 한 번 더 확인(옛 응답 덮어쓰기 없음). ③ **판정 전체 시간 제한 8초**(`CHECK_TIMEOUT_MS`) — ready·활성화·응답 대기 어디서 멈춰도 다음 확인이 막히지 않음. ④ **판정 시점 추가**: 시작 즉시 1회, 워커 활성화 메시지, 설정 화면 진입(`ensureOfflineCheck`, 재확인 횟수 초기화). 기존 3개 이벤트도 유지 |
| `app/src/sw/sw.ts` | `activate` 때 열린 창 전부(제어 전 포함)에 `DETOUR_WORKER_ACTIVATED` 메시지 → 페이지가 즉시 재판정 |
| `app/src/sw/messages.ts` | `MSG_WORKER_ACTIVATED` 상수 |
| `app/src/screens/Settings/index.tsx` | 진입 시 `ensureOfflineCheck()` 1회 (표시 조건은 그대로 `offlineReady`) |

판정 기준은 그대로 **실제 캐시 내용**입니다. 워커가 프리캐시 목록 전부를 `matchPrecache`로 하나씩 확인해 `{total, cached}`를 돌려주고, 페이지는 이 페이지를 워커가 제어 중이고 `total > 0 && cached === total`일 때만 준비 완료로 봅니다. 응답이 없거나(null·시간 초과) 오류면 이전 판정을 유지하고 재확인을 이어 갑니다.

## 3. 회귀 테스트 (순서 뒤바뀜·누락)

`app/src/sw/pwa.test.ts` — "제어 여부·캐시 개수" 상태를 가진 가짜 워커로 실제 순서를 흉내 냅니다(가짜 타이머).

| 테스트 | 확인 |
|---|---|
| controllerchange가 먼저 오고 등록 콜백까지 모두 "제어 전"에 끝난 뒤 이벤트가 더 없음 | 간격 재확인으로 표시 (경로 a) |
| 프리캐시가 10/52일 때 이벤트가 다 지나감 → 나중에 52/52 | 재확인으로 표시 |
| 판정 도중 controllerchange·활성화 메시지 도착, 첫 응답(51/52)이 늦게 옴 | 동시 실행 1개, 끝난 뒤 재판정으로 표시 (경로 c) |
| 첫 판정이 영원히 응답 없음 | 8초 시간 제한 뒤 다음 판정으로 표시 (경로 b) |
| 워커 활성화 메시지 / 다른 메시지 | 활성화 메시지만 재판정 |
| 준비 완료 뒤 | 재확인 멈춤(60초 동안 추가 호출 0) |
| 재확인 60회 상한 뒤 | 멈춤 → 설정 화면 진입(`ensureOfflineCheck`)으로 다시 판정 |
| 서비스 워커 미지원 환경 | `ensureOfflineCheck` 아무것도 안 함 |

`app/src/screens/Settings/SettingsOffline.test.tsx` — 앞선 판정이 모두 보류로 끝난 뒤 설정 화면에 들어오면 간격 재확인(1초)보다 먼저 즉시 판정해 카드가 뜸(500ms 안).
