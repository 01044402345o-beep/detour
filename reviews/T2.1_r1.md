## 발견 사항

### T2.1-M-01 — 언어 라디오 그룹에 키보드 이동·단일 Tab 진입점이 없음

- **위치:** `app/src/screens/Lang/index.tsx:51–65`, `app/src/screens/Settings/index.tsx:44–58`; 각 화면 테스트.
- **문제:** 버튼을 `role="radio"`로 노출하고 `aria-checked`는 갱신하지만, 모든 버튼이 기본 Tab 순서에 남고 방향키 처리도 없습니다. 선택된 언어에 포커스한 뒤 방향키를 눌러도 다음 언어 선택/포커스가 이동하지 않습니다. Tab·Space로 개별 버튼을 조작할 수는 있으나, 라디오 그룹으로 안내되는 컨트롤의 키보드 동작과 일치하지 않습니다.
- **근거:** PRD 7장 접근성 취지와 본 검토의 라디오 그룹 점검 대상. 두 구현 모두 `onClick`만 있고 `tabIndex`·`onKeyDown` 또는 네이티브 radio input이 없습니다. 기존 테스트는 클릭 및 ARIA 상태만 검사하므로 통과해도 이 누락을 검출하지 못합니다.
- **권장 수정안:** 같은 name의 네이티브 `input type="radio"`와 label을 사용하거나, 선택 항목만 `tabIndex=0`으로 두고 나머지는 -1로 설정하여 방향키 순환·포커스 이동·즉시 선택을 구현합니다. 두 화면에 선택 항목으로의 Tab 진입, 방향키 선택과 끝↔처음 순환, 선택 후 문구·저장값 갱신 회귀 테스트를 추가합니다. 기존 44px 클릭 영역과 포커스 표시를 유지합니다.

### T2.1-L-01 — 공용 토스트가 가용 폭의 절반 정도로 축소됨

- **위치:** `app/src/styles/ui.css:295–310` (`.ui-toast`), `app/src/ui/Toast.tsx`; 관찰 위치는 캡처 하단의 “S01 앱 · JA · 잠긴 거점 토스트”. **수정 소유: T2.0 공용 UI/스타일, T2.1 화면 아님.**
- **문제:** 화면 좌우에 여유가 있는데 토스트가 약 195px 폭으로 좁아져 일본어 안내가 두 줄로 접힙니다. 두 줄 자체는 오류가 아니고 캡처에서도 내용 잘림은 없지만, 공용 레이아웃이 사용할 수 있는 폭을 불필요하게 제한합니다.
- **근거:** 절대 배치 요소가 `left:50%`, `width:auto`, `right:auto` 상태여서 shrink-to-fit 계산 시 남은 오른쪽 절반 폭을 기준으로 줄어듭니다. `max-width:calc(100% - 32px)`는 상한일 뿐 그 너비를 확보하지 않고, `translateX(-50%)`도 배치 계산 이후의 이동입니다. Home은 `toast(t('home.soonToast'))`만 호출하고 별도 토스트 스타일·줄바꿈을 넣지 않으므로 화면 결함으로 돌릴 근거가 없습니다.
- **권장 수정안:** 공용 `.ui-toast`에 `width:max-content`와 기존 최대 너비를 조합하거나, 좌우 여백을 명시한 컨테이너로 전체 가용 폭 안에서 내용 크기를 계산하도록 수정합니다. 긴 문구의 자연스러운 여러 줄 표시는 허용하고 `white-space:nowrap`으로 강제하지 않습니다. coordinator가 공용 소유자에게 배정하고 EN·JA·ZH의 긴 토스트를 360·390·430px에서 확인하면 됩니다.

## 기능·이용 기록 판단

- **언어:** 첫 실행 기본 EN, 선택 즉시 store·UI 변경, 시작 시 홈 이동, 설정에서 문구·탭바 동시 전환과 localStorage 저장이 구현·검증되어 있습니다. 화면 테스트의 “새로고침 후 유지” 검증은 실제 새로고침이 아니라 저장 문자열 확인까지입니다. 유지 동작은 공용 persist 계약에 의존하며 화면의 별도 오류는 발견하지 못했습니다.
- **홈:** 원도심/지도 보기/오늘의 코스는 코스로 이동하고, 잠긴 두 거점·1박 배너는 토스트를 표시하며 현재 화면을 유지합니다. 오늘의 코스는 실제 course 데이터와 정류장 목록으로 표시하고, 오늘의 문장은 `ssd/ssd-2`에서 가져와 선택 언어의 발음·뜻과 듣기를 제공합니다.
- **기록:** `screen_view`는 T2.0 계약대로 라우터에 맡기며 화면에서 중복 기록하지 않습니다. Home의 `phrase_play`는 ListenButton의 `speak()` 반환값이 `started`인 뒤 `onPlay`로 기록합니다. `src:'phrase'`, `placeId:'ssd'`, `phraseId:'ssd-2'`는 실제 데이터와 일치하고, `logEvent` false 시 DEV 경고도 있습니다. 재생 거절 시 미기록 테스트가 있습니다. 여기서 started는 공용 TTS의 요청 수락 계약이며 음성 실제 완료 이벤트로 오해하지 않았습니다.
- **설정:** `/report` 진입, 초기화 확인·취소, 주문·저장·제보·기록 삭제 및 언어 유지, 언어 선택으로 이동이 테스트됩니다. 초기화 후 새 `screen_view(lang)` 1건이 남는 것은 새 화면 이동 기록이므로 결함이 아닙니다.
- **정정 연락처:** 안내와 `TAKEDOWN_CONTACT` 표시 자리가 있고 현재 값은 null입니다. T2.1은 자리 마련, T4.4 확정→T4.1a 반영을 명시하므로 현 단계 결함으로 세지 않습니다. 최종 반영 시 실제 연락 가능한 값이 필요합니다.
- **하드코딩:** 사용자 안내는 사전, 코스·문장은 데이터로 공급됩니다. 브랜드 문자열은 기존 `hardcodeCheck.ts` 허용 목록, 언어 자칭은 `LANG_NAMES`, 아이콘 문자·숫자는 장식/데이터 표현입니다. 오늘의 문장 ID 고정은 이 데모의 콘텐츠 선택이며 번역 문구 하드코딩이 아닙니다.

## 목업 차이·접근성 판단

- **가짜 상태바 생략:** 웹앱에서 OS 상태바를 중복 그리지 않는 변경으로 타당합니다. safe-area 여백도 반영되어 있습니다.
- **검색창 생략:** 목업의 검색창은 동작 없는 장식이고 F-02·T2.1에도 검색 기능 요구가 없습니다. 동작하지 않는 검색 입력을 제시하지 않는 변경으로 수용 가능합니다. 카드들의 상단 위치가 달라지는 것은 이 생략과 상태바 제거의 결과입니다.
- **한국어 언어 부제 생략:** English/日本語/简体中文 자칭으로 선택 가능하고 한국어 부제는 필수 정보가 아닙니다. 발음 표기 안내 추가는 F-01에 부합합니다.
- **오늘의 코스·정정 안내·초기화 확인 시트 추가:** 목업에 없거나 부족한 부분을 PRD·task 요구에 맞춘 것으로 타당합니다. 오늘의 코스 때문에 오늘의 문장이 아래로 밀리지만 전체 길이 캡처에 존재합니다.
- **색 변경:** 주황 텍스트/버튼의 `--acc-d` 사용, 잠긴 카드의 그림만 흐리게 처리, 1박 배너 흰 글자 불투명 표시, 언어 선택 라벨 밝기 조정은 대비를 위한 변경으로 타당합니다. 장식 로고·그림의 색을 일반 본문 텍스트로 취급하지 않았습니다. 새 화면 색 조합 전체의 브라우저 픽셀 대비 자동 검사를 수행한 것은 아닙니다.
- **44px:** 화면 고유 언어 버튼·지도 링크·거점·배너에 `--touch` 최소 크기가 있고, 나머지 클릭 요소는 공용 Button/CardButton/ListenButton을 사용합니다. 20px 코스 번호나 언어 배지는 독립 클릭 대상이 아닙니다. CSS 검토상 새로운 최소 터치 크기 위반은 발견하지 못했습니다. 라디오 이름·선택 상태·포커스 스타일은 있으나 키보드 그룹 동작은 M-01 수정이 필요합니다.

결론: T2.1의 주요 기능 누락은 발견하지 못했지만 M-01을 해결하고 재검토해야 합니다. L-01은 공용 UI 소유자에게 전달하며 화면 파일의 우회 스타일로 수정하지 않는 것이 적절합니다.
