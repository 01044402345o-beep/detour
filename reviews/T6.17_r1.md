## M-01 — 전환 중 약 0.20초 동안 이전·다음 묶음이 같은 자리에 동시에 보인다

**위치:** `app/src/ui/GuidePlayer.css:171–189`, `app/src/ui/GuidePlayer.tsx:272–290`.

**근거:** 비활성으로 바뀐 묶음은 opacity가 0.28초 동안 1→0으로 줄고 visibility는 0.28초 뒤에 hidden이 된다. 새 활성 묶음은 visibility가 즉시 visible이 되고, 0.08초 뒤부터 opacity가 0→1로 증가한다. 따라서 전환 후 0.08~0.28초에는 같은 grid-area에 배치한 두 문단이 동시에 그려진다. 첫 묶음에서 다음 묶음으로 자동 진행하거나 이전/다음을 눌러도 발생한다. 글자가 같은 줄 위치에 겹치므로 짧게라도 원고를 읽기 어렵고, 이 동안 두 묶음 모두 visibility가 visible이어서 “지금 묶음만 보임·나머지는 화면 읽기에서 제외”도 유지되지 않는다. 정지 캡처와 현재 CSS 문자열 테스트로는 잡히지 않는다.

**수정안:** 이전 묶음은 전환 즉시 visibility:hidden으로 감추고 새 묶음에만 fade-in을 적용하는 방식이 가장 단순하다. 반드시 fade-out을 유지하려면 이전 묶음이 완전히 사라진 뒤 새 묶음을 표시하는 순차 전환을 만들고, 비활성 묶음의 접근성 노출은 별도로 즉시 차단한다. grid 배치는 유지해 높이는 고정한다.

**검증:** 일반 모드에서 자동/수동 전환 후 0·100·200·300ms의 두 묶음 visibility/opacity 및 표시 상태를 검사하고, 빠른 연속 넘기기도 확인한다. reduced-motion에서는 즉시 하나만 보여야 한다. 현재 테스트의 CSS 정규식은 이러한 타이밍 오류를 통과시킨다.

## L-01 — 전체 글 버튼의 행동 이름과 pressed 상태가 뒤섞인다

**위치:** `app/src/ui/GuidePlayer.tsx:324–332`, `app/src/ui/GuidePlayer.test.tsx:283–302`.

**근거:** 전체 글을 펼치면 버튼 이름은 “Two sentences at a time / 2文ずつ表示 / 每次显示两句”로 바뀌지만 aria-pressed는 true가 된다. 화면 읽기에서는 “2문장씩 표시, 눌림”으로 전달될 수 있는데 실제 화면은 전체 글이다. 다음에 실행할 행동을 이름으로 삼는 버튼과 현재 상태를 나타내는 토글 모델이 섞여 있다. 테스트도 이 조합을 그대로 정답으로 고정하고 있다.

**수정안:** 두 방식 중 하나로 통일한다. (1) 이름은 항상 “전체 글 보기”로 유지하고 aria-pressed만 바꾼다. (2) 현재의 행동 이름 전환을 유지하고 aria-pressed를 제거해 일반 행동 버튼으로 제공한다. DESIGN.md의 버튼 설명과 해당 테스트도 선택한 의미에 맞춘다.

**검증:** 전체 글을 펼친 상태와 접은 상태에서 접근 가능한 이름·역할·상태가 실제 화면 모드와 모순되지 않는지 확인한다.

## 나머지 확인 결과와 테스트 한계

- **재생 상태:** start의 onSentence가 현재 문장과 묶음을 함께 갱신한다. 정지 후 같은 묶음은 멈춘 문장에서, 다른 묶음은 그 묶음 첫 문장에서 재생한다. 다른 묶음을 봤다가 원래 묶음으로 돌아오면 기존 멈춘 문장에서 이어 듣는 현재 동작은 테스트에 명시되어 있다. 완주 시 마지막 묶음 유지·재생 시 0번, 완주 후 수동 넘기기 시 선택 묶음 재생, 오류 시 현재 묶음에서 재시도, 재생 중 속도 변경 시 현재 문장에서 재시작하는 흐름에 별도 결함은 찾지 못했다.
- **이전 재생 콜백:** 실제 guideTts의 finish는 run.done을 세우고 utterance의 onstart/onend/onerror를 해제한다. 새 play가 이전 실행의 stopped를 동기로 알린 뒤 GuidePlayer.start가 playing=true와 새 페이지를 설정하므로, 정상 엔진 계약 안에서 늦은 이전 콜백이 페이지를 되돌린다고 판단할 근거는 없다. 다만 UI fakeTts는 실제 엔진과 이전 onEnd 통지 순서가 다르고 이전 실행 콜백을 보관하지 않아, 엔진 결합 회귀까지 증명하는 테스트는 아니다.
- **언어·닫기:** 언어 변경은 cur/page/ended/playing을 초기화하고 effect 정리에서 기존 음성을 정지한다. 닫기는 정지하고 다시 열기는 0번부터 시작한다. showAll과 속도는 닫았다 열어도 유지되는데, 이를 초기화해야 한다는 명시 요구가 없어 결함으로 세지 않았다.
- **높이·움직임:** 모든 묶음이 정상 grid item으로 동일 셀에 남아 있어 visibility:hidden인 묶음도 높이 계산에 참여한다. 제공 캡처에서도 언어별 첫·다음 묶음의 시트 높이가 같다. reduced-motion 선언은 활성·비활성 양쪽의 transition과 transform을 제거한다. 다만 재생 상태 줄·오류 안내가 생기거나 없어질 때의 시트 높이는 별개이며 “묶음 넘김 시 높이 고정”으로 범위를 읽었다.
- **접근성:** 안정 상태의 visibility:hidden은 비활성 글을 숨기는 적절한 방식이다. 이전/다음의 번역된 이름, 처음·끝 disabled, 44px 화살표, 전체 글 버튼 최소 높이, focus-visible 스타일을 확인했다. Sheet가 포커스 진입·Tab 순환·닫기 후 복귀를 담당한다. n/N의 role=img는 접근 가능한 번역 이름을 제공하므로 정보 누락으로 보지는 않지만 숫자 진행 정보를 “이미지”로 알리는 의미는 어색하다. 장기적으로 일반 텍스트와 읽기 전용 번역 문구로 표현하는 편이 자연스럽다. 자동 재생 중 화면 읽기와 충돌할 수 있으므로 무조건 live region으로 바꾸라고 권하지 않는다.
- **대비:** 새 글자·카운터·버튼은 기존 ink/mute/blue와 ground/surface 토큰을 사용한다. mute 토큰에 명시된 ground 대비는 5.72:1이며, 캡처에서 새 활성 요소의 대비 문제는 발견하지 못했다. 비활성 화살표의 흐린 표시와 활성 버튼을 구분했다.
- **번역:** ja의 前へ/次へ/全文を見る/2文ずつ表示, zh의 上一段/下一段/查看全文/每次显示两句는 맥락상 이해 가능하다. ja의 “{total}のうち{n}”는 무엇의 순번인지 약하지만 필수 수정 수준은 아니다. “아래 가이드를 읽어 주세요” 안내도 아래 묶음·넘기기·전체 글 경로가 있어 모순되지 않는다. 패치와 세 언어 사전의 추가 키는 일치한다.
- **묶음 테스트:** 문단 경계, 홀수 문장, 긴 두 문장 분리, 실제 원고의 순서·중복·묶음 크기 검증은 유효하다. 다만 상한과 정확히 같은 길이의 테스트가 없어 `<= max`를 `< max`로 바꾸는 변이는 충분히 겨냥하지 않는다. 실제 원고 검사는 chunkOf 길이만 확인하며 각 문장→묶음 매핑까지는 검사하지 않는다. 별도 변이 실행은 하지 않았다.
- **UI 테스트:** 주요 상태 경로는 커버하지만 재열기, 페이지 진행 후 오류·천천히·완주 후 수동 넘김, 실제 엔진의 지연 콜백과의 결합 검증은 보완 여지가 있다. CSS 테스트는 stage의 display:grid를 삭제해도 통과할 수 있고, 실제 높이·전환 겹침을 검사하지 않는다. M-01 수정 검증에 브라우저 기반 표시 검사를 추가하는 것이 우선이다.
- **문서:** DESIGN.md는 문단별 1~2문장과 언어별 상한까지 구현과 일치한다. PRD F-19의 “2문장씩”은 상세 설계의 축약으로 읽을 수 있으나 더 엄밀하게는 “최대 2문장씩”이라고 쓰면 한 문장 묶음과도 바로 맞는다.
